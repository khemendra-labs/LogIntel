# LOGINTEL — M6.2 IMPLEMENTATION & VERIFICATION REPORT

## 1. Executive Summary

Milestone **M6.2 — Linux Process & Execution Telemetry** is the first implementation milestone of the **M6 (Advanced Linux Telemetry & Host Intelligence)** program. Building directly upon the readiness audit of M6.1, M6.2 establishes deterministic, reliable, forensic-grade ingestion and canonical normalization of Linux host execution telemetry via the Linux audit subsystem (`auditd` / `/var/log/audit/audit.log`).

Key accomplishments in M6.2:
1. **AuditLogCollector & AuditParser:** Implemented streaming ingestion of raw audit records with persistent byte-offset and inode tracking, multi-line correlation (`msg=audit(epoch.seq:id)`), hex argument decoding, and process context extraction.
2. **Deterministic Process Ancestry:** Implemented `ProcessAncestryResolver` with multi-generation parent-child relationship tracking, PID reuse protection (`host:pid:timestamp:executable:sequence`), and strict epistemic classification (`OBSERVED`, `INFERRED`, `UNKNOWN`).
3. **Forensic Evidence & Sanitization:** Guaranteed raw forensic integrity (`raw_message` preserved strictly unaltered) while sanitizing credentials and secrets deterministically in display and canonical representations (`process.command_line`, `summary`).
4. **Zero Schema Migrations:** Fully accommodated all execution telemetry within the existing canonical schema via `metadata_json` without creating Migration 6.
5. **Rigorous Verification:** 20 dedicated security tests (`M62-SEC-001` through `M62-SEC-020`), 9 telemetry unit tests, 2 determinism tests over 10 repetitions, 1 real-host audit integration test, synthetic replay benchmark over 3 iterations (median 8,278.4 eps), and 44 frontend Vitest tests.

## 3. Scope

M6.2 strictly implements:
- `auditd` ingestion via `AuditLogCollector` subclassing `Collector` and leveraging `FileTailer`.
- Audit event parsing for `SYSCALL`, `EXECVE`, `PROCTITLE`, `USER_START`, and `USER_END`.
- Argument reconstruction, hexadecimal decoding, and quoted argument parsing.
- Credential masking for passwords, API tokens, Authorization headers, and bearer credentials while preserving safe command flags (`-p 80`, `mkdir -p`).
- Process identity and ancestry reconstruction with PID reuse protection.
- Canonical event mapping (`PROCESS_EXECUTION`, `AUDIT_SESSION_START`, `AUDIT_SESSION_END`).
- Epistemic state attribution (`OBSERVED`, `INFERRED`, `UNKNOWN`).

**Strict Non-Goals Preserved:**
No network/socket telemetry, no filesystem monitoring, no container/Docker telemetry, no eBPF, no full syscall tracing, no cloud telemetry, no remote collection, no AI autonomous agents, no automated remediation/firewall/process killing, and strictly no Migration 6.

## 6. AuditLogCollector

- Subclasses base `Collector` to preserve existing ingestion architecture.
- Reuses `FileTailer` for cursor state, byte offset persistence, and inode tracking across log rotations and truncations.
- Collects raw records line-by-line, buffering related records until `audit_id` changes or timeout occurs.
- On file truncation or rotation, resets offset appropriately without losing or skipping records.
- Ingestion telemetry tracked in `ingestion_state` table (`byte_offset`, `total_records_ingested`, `error_count`).

---

## 7. AuditParser

- Extracts audit header: `type=TYPE msg=audit(epoch.seq:id): ...`
- Parses key-value pairs while respecting double-quoted strings containing spaces or escaped characters.
- Groups records by `audit_id = f"{epoch}.{seq}:{rec_id}"`.
- Correlates multi-record execution sequences:
  - `SYSCALL` provides PID, PPID, UID, EUID, AUID, SES, COMM, EXE, SUCCESS, EXIT.
  - `EXECVE` provides argument count (`argc`) and arguments (`a0`, `a1`, ...).
  - `PROCTITLE` provides process title hex representation.
- Preserves raw evidence unaltered in `raw_message` as newline-delimited raw audit records.

---

## 8. EXECVE Processing

- Dynamically discovers all argument keys (`a0`, `a1`, `a2`, ...).
- Implements `decode_audit_hex`:
  - Differentiates quoted literals (e.g., `a0="/bin/ls"`) from unquoted hex-encoded strings (e.g., `a0=2F62696E2F6C73`).
  - Correctly prevents misinterpretation of quoted ASCII strings as hex bytes.
  - Replaces non-printable or null characters with spaces.
- Joins arguments deterministically to reconstruct `process.command_line`.
- Applies resource bounds: maximum 512 arguments, maximum 16,384 characters total command line.

---

## 9. PROCTITLE Processing

- Decodes hex-encoded null-delimited process titles.
- Injects single spaces for null byte separators (`\x00`).
- When `EXECVE` and `PROCTITLE` are both present, `EXECVE` arguments serve as authoritative `command_line` while `proctitle` is preserved in `metadata_json` with discrepancy detection.

---

## 10. SYSCALL Processing

- Extracts process metadata:
  - `pid`, `ppid`
  - `uid`, `euid`, `suid`, `fsuid`
  - `gid`, `egid`, `sgid`, `fsgid`
  - `auid` (Audit UID / Login UID)
  - `ses` (Session ID)
  - `comm` (Command basename)
  - `exe` (Full binary path)
  - `success` (yes/no mapped to SUCCESS/FAILURE)
  - `exit` (Exit code integer)
  - `arch` (Syscall architecture identifier)
  - `key` (Audit rule tag)

---

## 11. Audit Session Processing

- Ingests `USER_START` and `USER_END` records generated by PAM and system authentication.
- Maps `USER_START` to canonical `AUDIT_SESSION_START` with outcome `SUCCESS`.
- Maps `USER_END` to canonical `AUDIT_SESSION_END`.
- Preserves `auid`, `ses`, terminal (`tty`), and PAM unit in `metadata_json`.
- Distinguishes login identity (`auid`), real identity (`uid`), and effective identity (`euid`).

---

## 12. Process Identity

Process identity is designated as a **deterministic collision-resistant process identity**:
- Built via `build_process_identity(host, pid, timestamp, exe, audit_seq)`
- Combines `host`, `pid`, ISO `timestamp`, `exe`, and `audit_seq`.
- Bounded process lifecycle tracking preserves separate identity keys for successive executions that happen to reuse the same operating system PID.

---

## 13. Process Ancestry

Implemented `ProcessAncestryResolver`:
- Constructs parent-child-grandchild ancestry chains.
- Strict epistemic state attribution:
  - `OBSERVED`: Audit telemetry explicitly reports the PID/PPID relationship, and the parent is matched in the index.
  - `INFERRED`: Telemetry correlated across temporal boundaries where direct linkage is incomplete.
  - `UNKNOWN`: Missing PPID or PPID=0 (swapper/idle/container root). Never manufactures `SPAWNED` without evidence.
- Multi-generation hierarchy navigation (`chain.depth`, `chain.root`, `chain.leaf`).

---

## 14. Credential / Secret Handling

Multi-tier sanitization architecture:
```text
Raw Ingestion: raw_message retained 100% unaltered with exact credentials for forensic proof.
Canonical Representation: process.command_line and summary masked deterministically.
Downstream Exposure: AI advisory and UI display receive only masked credentials.
```
Masking Coverage:
- `--password=VALUE`, `--password VALUE`
- `-p VALUE` (while preserving port arguments like `-p 80` or directory creation `mkdir -p`)
- `password=VALUE`, `passwd=VALUE`
- `token=VALUE`, `api_key=VALUE`, `secret=VALUE`
- `Authorization: Bearer VALUE`
- False-positive resistance verified via unit tests (`-p 443`, `-p 8080`, `mkdir -p /tmp/dir`).
- Raw audit evidence constitutes sensitive forensic material requiring restricted access controls.

## 15. Canonical Event Mapping

Telemetry is mapped into existing `CanonicalEvent` fields without schema changes:
- `event_type`: `PROCESS_EXECUTION`, `AUDIT_SESSION_START`, `AUDIT_SESSION_END`
- `action`: `process_execution`, `session_start`, `session_end`
- `outcome`: `SUCCESS` or `FAILURE`
- `process.name`: Extracted from `comm` or `exe`
- `process.pid`: Extracted from `pid`
- `process.ppid`: Extracted from `ppid`
- `process.executable`: Full path from `exe`
- `process.command_line`: Sanitized command line from `EXECVE` / `PROCTITLE`
- `raw_message`: Pristine raw audit record(s)
- `metadata`: Contains `auid`, `euid`, `ses`, `audit_sequence`, `audit_id`, `comm`, `exit_code`, `proctitle`.

## 16. Fingerprinting & Deduplication

- Every audit event receives a deterministic SHA-256 fingerprint generated from `(timestamp, host, source, event_type, process.pid, process.executable, process.command_line, raw_message)`.
- Replay tests verify that duplicate ingestion of the exact same audit record produces an identical fingerprint and is rejected by the database unique constraint without error or corruption.

## 17. Rotation & Restart Safety

- Offset state is updated only after records are successfully yielded.
- If the file inode changes (log rotation via `logrotate`), `FileTailer` detects the change, processes remaining data from the old inode, and begins tailing the new inode from byte offset 0.
- If the file shrinks (truncation), offset is reset to 0 to prevent missed events.
- Ingestion engine restart tests confirm that re-reading from saved offset yields 0 duplicate events.

## 29. Known Limitations

The following limitations are explicitly documented and carried forward to M6.3+:
1. **Audit Rule Configuration Prerequisite:** `auditd` requires explicit kernel audit rules (e.g. `auditctl -a always,exit -F arch=b64 -S execve -k exec_monitor`) to generate `EXECVE` records for all host processes. If rules are unconfigured, `auditd` does not emit `EXECVE`, which LogIntel treats as `AUDIT RECORD NOT AVAILABLE` rather than asserting "no process execution occurred".
2. **Container Namespace PID Mapping:** Audit records capture root PID namespace identifiers. Container-internal virtual PIDs require future M6.5 container namespace mapping.
3. **Short-Lived Ephemeral Executions:** Rapid short-lived executions without backlog tuning may be dropped if the kernel audit backlog buffer overflows (`auditctl -b`).
4. **Environment Variables:** `auditd` does not capture environment variables passed to `execve` by default; environment forensics deferred to future eBPF / audit enhancements.
5. **Interactive Browser Verification:** Desktop frontend verified via automated tests and build, not live interactive browser sessions.
6. **Historical Database Dataset:** Historical row-level reconciliation unexecutable due to absence of authoritative historical baseline dataset.
