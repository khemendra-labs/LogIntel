## 9. Asynchronous Isolation Analysis

Source inspection of [`InvestigationMultiHostWorkbench.tsx`](file:///home/khemendra-labs/LogIntel/apps/desktop/src/features/InvestigationMultiHostWorkbench.tsx) revealed:

1. **Race Protection Mechanism:**
   - Employs `useRef`: `activeCaseRef` (initialized to `caseId`) and `activeHostRef` (initialized to `null`).
   - In `loadDossier`: validates `if (activeCaseRef.current === caseId)` before updating state.
   - In `loadHostTimeline`: validates `if (activeCaseRef.current === caseId && activeHostRef.current === hostId)` before setting `timelineData`.
2. **Identified Race Window:**
   - In `useEffect([caseId])` (lines 61–66):
     ```typescript
     activeCaseRef.current = caseId;
     setSelectedHostId(null);
     setTimelineData(null);
     loadDossier();
     ```
     `setDossier(null)` is omitted. The previous case's dossier remains in state while the fetch for the new case is in-flight.
     The content panes are shielded by `!loading && !error && dossier`, but header metrics display the previous case's counts until `loadDossier()` completes.
3. **Request Cancellation:**
   - No `AbortController` / `AbortSignal` is attached to the fetch calls. In-flight HTTP requests run to network completion, though state updates are ignored if the ref ID has changed.
