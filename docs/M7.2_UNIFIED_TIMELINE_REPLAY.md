## 1. Architectural Mission

Milestone M7.2 introduces the first core analyst-facing operation of Program M7:
> **A deterministic, evidence-centric investigation timeline projection with interactive replay and synchronized graph/evidence navigation.**

### Core Invariants:
1. **Preservation of Epistemic Status:**
   - Forensic facts are categorized into `OBSERVED`, `INFERRED`, or `UNKNOWN`.
   - `UNKNOWN` is never transformed to `FALSE`.
   - `UNAVAILABLE` telemetry is never transformed to `SAFE`.
   - `INFERRED` relationships or correlations are never promoted to `OBSERVED`.
2. **Deterministic Reconstruction:**
   - Replay is a deterministic chronological projection of available case-scoped evidence.
   - It is strictly **not** AI generation, simulation, or probabilistic prediction.
   - Identical datasets, scopes, and filter parameters always yield the identical ordered timeline and session fingerprint.
3. **Immutability of Authoritative Forensics:**
   - All timeline projections and replay sessions are read-only views over existing telemetry (`events`, `alerts`, `incidents`, `host_threat_graph`, `case_evidence_references`).
   - Replay navigation and scrubbing state are transient UI state; no mutation occurs to `logintel.db` or `cases.db`.
4. **Synchronized Multi-Modal Navigation:**
   ```text
   Timeline Selection
           ↕
      Graph Pivot
           ↕
   Evidence Reference
           ↕
     Canonical Event
           ↕
      Original Source
   ```

## 2. Timeline Data Model & Semantics

The domain model is implemented in `apps/engine/src/logintel/timeline/models.py`.

### 2.1 Timeline Item Structure
```python
class InvestigationTimelineItem(BaseModel):
    timeline_id: str
    case_id: int
    timestamp: str
    timestamp_precision: TimestampPrecision  # "SECOND" | "MILLISECOND" | "UNKNOWN"
    host_id: str
    event_type: str
    source_layer: TimelineSourceLayer        # "EVENT" | "ALERT" | "EVIDENCE" | "HOST_TELEMETRY" | "INCIDENT" | "AUDIT"
    source_id: str
    entity_refs: list[str]
    relationship_refs: list[str]
    detection_refs: list[str]
    incident_refs: list[int]
    evidence_refs: list[str]
    epistemic_status: EpistemicStatus        # "OBSERVED" | "INFERRED" | "UNKNOWN"
    collection_status: CollectionStatus      # "SOURCE_AVAILABLE" | "SOURCE_UNAVAILABLE" | "RULE_NOT_CONFIGURED" | "NO_EVENT_OBSERVED" | "TELEMETRY_DROPPED" | "UNKNOWN"
    display_summary: str
    provenance: dict[str, Any]
    is_bookmarked: bool = False
```

### 2.2 Deterministic Ordering Guarantee
Timeline items are ordered via a four-tier deterministic tie-breaking key:
```python
sort_key = (
    item.timestamp,
    LAYER_PRIORITY[item.source_layer], # AUDIT=0, EVENT=1, HOST_TELEMETRY=2, ALERT=3, EVIDENCE=4, INCIDENT=5
    item.source_id,
    item.timeline_id,
)
```
- Equal timestamps do **not** invent sub-second ordering. Instead, deterministic source-layer priority and stable alphanumeric identifiers disambiguate records.
- Preserves available timestamp precision without fabricating artificial fractions.

## 3. Interactive Replay Controller Architecture

### 3.1 Replay Session Structure
```python
class TimelineReplayFrame(BaseModel):
    frame_index: int
    timestamp: str
    item: InvestigationTimelineItem
    active_entities: list[str]
    active_hosts: list[str]
    epistemic_status: EpistemicStatus

class TimelineReplaySession(BaseModel):
    case_id: int
    total_frames: int
    frames: list[TimelineReplayFrame]
    session_fingerprint: str
    deterministic_order: list[str]
```

### 3.2 Navigation & Transport Controls
- **Transport:** Play (`▶`), Pause (`⏸`), Step Forward (`▶|`), Step Backward (`|◀`), Jump to Start (`|◀◀`), Jump to End (`▶▶|`), Previous Evidence (`◁*`), Next Evidence (`*▷`).
- **Speed Rates:** `0.25x`, `0.5x`, `1.0x`, `2.0x`, `4.0x`.
- **Scrubber Bar:** Proportional range input providing instant random access to any frame index without reordering events.
- **Keyboard Shortcuts:** `Space` (Play/Pause), `ArrowRight` (Step forward), `ArrowLeft` (Step backward), `Home` (Jump start), `End` (Jump end).
- **Session Fingerprint:** Deterministic Blake2b cryptographic hash calculated across the serialized sequence of frame timeline IDs and timestamps.

## 4. Multi-Layer Investigation Telemetry Projection

The timeline aggregates authoritative evidence across six distinct operational layers:
1. **EVENT:** Canonical audit and telemetry records from `logintel.db` `events` table (process execution, network connections, file modifications).
2. **ALERT:** Detection engine triggers from `logintel.db` `alerts` table (MITRE rule violations, privilege escalation detections).
3. **EVIDENCE:** Explicitly curated evidence references registered in `cases.db` `case_evidence_references`.
4. **HOST_TELEMETRY:** Deep Linux host telemetry (auditd system calls, socket sessions, sudo invocations).
5. **INCIDENT:** Incident dossier lifecycle transitions and boundary correlations.
6. **AUDIT:** Immutable case governance audit log entries recorded in `cases.db` `case_audit_log`.

## 5. API Endpoints

Registered under `/api/v1/cases/{case_id}/timeline/*`:
- `GET /api/v1/cases/{case_id}/timeline/unified`: Filtered, bounded timeline items with total count and deterministic Blake2b fingerprint.
- `GET /api/v1/cases/{case_id}/timeline/replay`: Frame-indexed replay session with entity/host activity states and session fingerprint.
- `GET /api/v1/cases/{case_id}/timeline/context/{timeline_id}`: Deep context resolution returning linked entities, alerts, evidence references, and traceable forensic path.
- `POST /api/v1/cases/{case_id}/timeline/{timeline_id}/bookmark`: Records an analyst bookmark reference in `cases.db` `case_evidence_references` without altering original forensic telemetry.
- `DELETE /api/v1/cases/{case_id}/timeline/{timeline_id}/bookmark`: Removes bookmark reference.
- `GET /api/v1/cases/{case_id}/timeline/unified/export`: Generates deterministic, case-scoped JSON or CSV export.
