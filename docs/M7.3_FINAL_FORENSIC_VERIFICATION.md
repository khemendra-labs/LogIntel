## 1. Executive Summary

Milestone M7.3 delivers the second major analyst-facing investigation capability of Program M7: **Logical Evidence Collections and a dedicated Forensic Evidence Workbench for organizing, reviewing, correlating, annotating, and exporting evidence references within an investigation.**

The core principle governing this milestone is:
```text
Evidence Collection  ≠  Copy of Evidence
```

Collections are logical analyst groupings of references to authoritative forensic records. They do not duplicate, alter, or delete raw or canonical forensic telemetry.

### Key Forensic Achievements:
1. **Zero Evidence Duplication:** Adding an evidence reference to a collection stores only a logical pointer (`source_type`, `source_id`, `role`, `epistemic_status`). Authoritative forensic records in `logintel.db` and `cases.db` remain uncopied and immutable.
2. **Strict Deletion Semantics:** Removing an evidence item from a collection or deleting an entire collection removes solely the analyst organizational grouping; under no circumstances is the underlying authoritative evidence or canonical event deleted.
3. **Epistemic & Review State Decoupling:** Forensic facts preserve their objective provenance (`OBSERVED`, `INFERRED`, `UNKNOWN`). Categorizing an item into a collection does not alter its epistemic status or automatically promote its review status.
4. **Dedicated Analyst Workbench:** A multi-layered interactive interface (`InvestigationEvidenceWorkbench.tsx`) that projects all case evidence, enables multi-dimensional filtering, provides deep provenance inspection, and supports cross-tool navigation to the Unified Timeline and Attack Graph.
5. **Strict Case Isolation:** All collection operations, workbench queries, annotations, and exports are strictly isolated per case. Zero cross-case data leakage occurs.
6. **No Schema Migrations (Migration 7 & 8 Rejected):** Existing case reference persistence and in-memory projection models satisfy all persistent and transient state requirements. Migrations remain frozen at 5.

## 4. Migration Evaluation

**Decision: Migration 7 = REJECTED, Migration 8 = REJECTED.**

Collections are represented using the existing `case_evidence_references` schema and JSON metadata capabilities:
- Collections are stored with `role="CONTEXTUAL"` and `source_type="evidence_collection"` in `case_evidence_references`.
- Collection membership items are stored with `role="SUPPORTING"` and tagged to the parent collection within `analyst_annotation`.
- Authoritative evidence referenced in collections remains unaltered.
- This design satisfies all functional and forensic requirements with **zero alterations** to `schema_migrations` or SQLite tables.
