## 1. Architectural Mission & Trust Hierarchy

Milestone M7.5 introduces a governed, analyst-directed threat hunting and structured query operation layer:

```text
RAW EVENT
    ↓
CANONICAL EVENT
    ↓
DETECTION
    ↓
ALERT
    ↓
INCIDENT
    ↓
ENTITY / RELATIONSHIP
    ↓
TIMELINE / GRAPH
    ↓
EVIDENCE
    ↓
FINDING
    ↓
HYPOTHESIS
    ↓
ANALYST ASSESSMENT
    ↓
LOCAL AI ADVISORY
```

### Primary Forensic Boundary Axiom:
```text
THREAT HUNTING  ≠  DETECTION
```
- A **Hunt** asks: *"Show me evidence matching this analyst-defined investigative question."*
- A **Detection** states: *"The deterministic detection engine has identified an event pattern according to an authoritative rule."*

### Critical Invariants:
1. A threat hunt match **never** automatically creates an authoritative detection, alert, or incident.
2. Threat hunting **never** modifies raw forensic telemetry in `logintel.db`.
3. Results of a hunt are references to evidence (`source_type`, `source_id`), never copies of raw event payloads.
4. Execution must be strictly governed: `DRAFT → VALIDATED → READY → APPROVED → EXECUTING → COMPLETED`.
5. Natural language describes the analyst question; execution requires a validated, type-aware, allowlisted structured query.
6. Execution must be bounded: strict limits on result count (max 500), time window (max 30 days), query complexity, and execution timeout. Exceeding limits deterministically returns `RESOURCE_LIMIT_EXCEEDED`.
7. Local AI assistance is strictly advisory (`AI proposal ≠ executed query`). The analyst must approve execution.

## 3. Database Schema & Migration Decision

### **DECISION: MIGRATION 7 / 8 / 9 IS REJECTED (0 NEW MIGRATIONS).**

#### Technical Justification:
1. `cases.db` already possesses the `case_query_history` table:
   ```sql
   CREATE TABLE IF NOT EXISTS case_query_history (
       query_id TEXT NOT NULL PRIMARY KEY,
       case_id INTEGER NOT NULL REFERENCES investigation_cases(case_id) ON DELETE CASCADE,
       proposal_id TEXT NOT NULL,
       query_template_id TEXT NOT NULL,
       parameters_json TEXT NOT NULL DEFAULT '{}',
       rationale TEXT NOT NULL,
       executed_by TEXT NOT NULL,
       executed_at TEXT NOT NULL,
       result_count INTEGER NOT NULL DEFAULT 0,
       execution_status TEXT NOT NULL DEFAULT 'SUCCESS',
       evidence_candidates_count INTEGER NOT NULL DEFAULT 0
   );
   ```
2. The `parameters_json` column cleanly accommodates the complete M7.5 structured query model, hunt intent, execution bounds, and result fingerprint without schema alteration.
3. Hunt results reference existing `case_evidence_references` and authoritative `events` in `logintel.db`.
4. Append-only audit entries are stored in `case_audit_log`.
5. Schema migrations remain frozen at version 5.
