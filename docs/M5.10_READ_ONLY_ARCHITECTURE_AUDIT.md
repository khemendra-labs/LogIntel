## 4. M5.10 Implementation Architecture

To fulfill all requirements of Milestone M5.10 without duplicating existing architecture, the following modular extensions will be implemented:

### 1. Domain Models (`apps/engine/src/logintel/ai/domain/investigation_temporal.py`):
- `TemporalEpisode`: Deterministic grouping of related evidence items into cohesive investigative episodes (`AUTHENTICATION_BURST`, `PROCESS_EXECUTION_EPISODE`, `PRIVILEGE_CHANGE_EPISODE`, `LATERAL_MOVEMENT_EPISODE`, `NETWORK_ACTIVITY_EPISODE`, `PERSISTENCE_EPISODE`).
- `TemporalTransition`: Explicit, evidence-backed transition between episodes or entities (`USER_TO_HOST`, `HOST_TO_HOST`, `USER_TO_PROCESS`, `PROCESS_TO_NETWORK_DESTINATION`, `PROCESS_TO_FILE`, `ALERT_TO_INCIDENT`, `INCIDENT_TO_ENTITY`) with `epistemic_status` (`OBSERVED`, `INFERRED`, `UNKNOWN`).
- `TemporalEvidenceChain`: Ordered sequence linking `Event A -> Relationship -> Entity -> Event B -> Transition -> Event C` with source citations.
- `TemporalGap`: Explicit telemetry or temporal gap (`NO_TELEMETRY`, `MISSING_HOST_VISIBILITY`, `MISSING_PROCESS_TELEMETRY`, `MISSING_NETWORK_TELEMETRY`, `TIMESTAMP_GAP`, `UNRESOLVED_TRANSITION`, `INSUFFICIENT_EVIDENCE`).
- `IncidentCampaignCorrelation`: Categorical campaign-level correlation between incidents (`SHARED_ENTITY`, `SHARED_ACCOUNT`, `SHARED_SOURCE`, `SHARED_DESTINATION`, `TEMPORAL_PROXIMITY`, `COMMON_SEQUENCE`, `COMMON_EVIDENCE`, `COMMON_TECHNIQUE`) with statuses `POTENTIALLY_RELATED`, `CORRELATED`, `INSUFFICIENT_EVIDENCE`, `UNRELATED`.
- `TemporalReconstructionDossier`: Top-level deterministic container combining episodes, transitions, evidence chains, gaps, campaign correlations, multi-host traces, and attack sequences.

### 2. Temporal Reconstruction Engine (`apps/engine/src/logintel/ai/temporal/reconstruction_engine.py`):
- Deterministic reconstruction algorithm taking `InvestigationCase`, `InvestigationGraph`, and `EvidenceCluster` inputs.
- Cross-host reconstruction tracking actor/process continuity across distinct infrastructure boundaries.
- Continuity analysis (`SAME_ACCOUNT_ACROSS_HOSTS`, `SAME_PROCESS_LINEAGE`, `SAME_SOURCE_IP`, `SAME_DESTINATION`).
- Transition review state management with strict separation from epistemic status (`epistemic_status` vs `review_state`).
- Temporal export engine supporting `JSON`, `CSV`, and `GraphML`.

### 3. API Integration (`apps/engine/src/logintel/api/routes.py`):
- `GET /api/v1/cases/{case_id}/timeline/reconstruction`: Full temporal reconstruction dossier.
- `GET /api/v1/cases/{case_id}/timeline/episodes`: Reconstructed temporal episodes.
- `GET /api/v1/cases/{case_id}/timeline/transitions`: Episode and entity transitions.
- `GET /api/v1/cases/{case_id}/timeline/gaps`: Temporal and telemetry gaps.
- `GET /api/v1/cases/{case_id}/timeline/sequences`: Attack sequences with chronological steps.
- `GET /api/v1/cases/{case_id}/timeline/incidents`: Cross-incident campaign correlations.
- `GET /api/v1/cases/{case_id}/timeline/incidents/{incident_id}/relations`: Incident relationship details.
- `POST /api/v1/cases/{case_id}/timeline/transitions/{transition_id}/review`: Analyst review for transitions (`ACCEPTED`, `REJECTED`, `PENDING_REVIEW`).
- `POST /api/v1/cases/{case_id}/timeline/explain`: Advisory local AI explanation of transitions and timelines.
- `GET /api/v1/cases/{case_id}/timeline/export`: Export reconstruction in JSON, CSV, or GraphML formats.

### 4. Desktop Frontend (`apps/desktop/src/`):
- TypeScript interfaces matching `investigation_temporal.py` in `apps/desktop/src/types/investigation.ts`.
- API client methods in `apps/desktop/src/lib/api.ts`.
- Dedicated component `InvestigationTemporalExplorer.tsx` in `apps/desktop/src/features/`.
- Integration into `InvestigationIntelligencePanel.tsx` under a new `"timeline"` / `"reconstruction"` subtab.
- State synchronization: selecting a timeline transition highlights related graph nodes/edges and evidence references.

## 5. Security & Boundary Guardrails

The following guardrails must be rigorously enforced throughout M5.10:
1. **Zero Authoritative Forensic Mutation:** Zero writes to `logintel.db`. All analyst reviews and temporal annotations persist to `cases.db`.
2. **Strict Epistemic Demarcation:** `OBSERVED` vs `INFERRED` vs `UNKNOWN` are preserved. Analyst acceptance (`ACCEPTED`) never converts `INFERRED` to `OBSERVED`.
3. **No Fabricated Confidence Scores:** No numerical confidence percentages, probabilities, or synthetic risk scores.
4. **Governed Query Bounds:** Hard limits on maximum episodes (<= 50), transitions (<= 100), sequence steps (<= 20), evidence references (<= 20), and gaps (<= 50).
5. **Zero External AI / Cloud Dependency:** AI explanations remain strictly advisory (`is_authoritative = False`) and execute solely via local loopback.
6. **Zero Shell / Subprocess Execution:** No subprocess or shell commands anywhere in the reconstruction or export pipelines.
7. **Cross-Case Isolation:** Case ID strictly partitions all temporal reconstructions, episodes, transitions, and campaign linkages.
