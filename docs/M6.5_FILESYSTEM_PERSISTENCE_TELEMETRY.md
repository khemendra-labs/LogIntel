## 1. Overview & Architectural Mission

Filesystem integrity and persistence telemetry is a critical pillar of Linux host monitoring. Threat actors who gain initial host access frequently install persistence hooks (cron jobs, systemd service drops, SSH keys, shell startup profiles) or tamper with core privilege databases (`/etc/passwd`, `/etc/sudoers`, `/etc/ld.so.preload`).

Milestone M6.5 introduces **bounded, deterministic, forensic-safe Linux filesystem & persistence telemetry** targeting High-Value Targets (HVTs) without the extreme CPU overhead, kernel crash risk, or buffer overflow pitfalls of recursive whole-filesystem inotify/fanotify monitoring:

```text
HIGH-VALUE PERSISTENCE TARGETS (cron, systemd, ssh, sudoers, ld.so)
                         ↓
FileIntegrityScanner (Extracts inode, mode, UID/GID, size, computes SHA-256)
                         ↓
FilesystemPersistenceCollector (Tracks state deltas across scanning cycles)
                         ↓
CanonicalEvent Generation (FILE_PERSISTENCE_DROP, FILE_INTEGRITY_MODIFY, FILE_PERSISTENCE_REMOVE)
                         ↓
Forensic Database (logintel.db events table, idempotent ingestion)
```

## 2. High-Value Target (HVT) Architecture

Instead of monitoring every file on the system, LogIntel explicitly defines and monitors the highest-value persistence and privilege vectors:

1. **Cron Persistence:**
   - `/etc/crontab`
   - `/etc/cron.d/`, `/etc/cron.daily/`, `/etc/cron.hourly/`, `/etc/cron.weekly/`, `/etc/cron.monthly/`
   - `/var/spool/cron/crontabs/`
2. **Systemd Service Drops:**
   - `/etc/systemd/system/`
3. **SSH User Persistence:**
   - `~/.ssh/authorized_keys`
4. **Shell & Environment Profiles:**
   - `~/.bashrc`, `~/.profile`, `/etc/profile`, `/etc/profile.d/`, `/etc/environment`
5. **Account & Privilege Control:**
   - `/etc/passwd`, `/etc/shadow`, `/etc/sudoers`, `/etc/sudoers.d/`, `/etc/group`
6. **Dynamic Linker Hijacking:**
   - `/etc/ld.so.preload`, `/etc/ld.so.conf`, `/etc/ld.so.conf.d/`

## 3. Core Filesystem Components (`logintel.filesystem`)

### 3.1 `FileState` & `TargetCategory`
Captures point-in-time forensic attributes:
- `path`: Canonical file path.
- `category`: `PERSISTENCE_CRON`, `PERSISTENCE_SSH`, `PERSISTENCE_SYSTEMD`, `PERSISTENCE_SHELL`, `ACCOUNT_PRIVILEGE`, `DYNAMIC_LINKER`, `CUSTOM`.
- `inode`, `size_bytes`, `mode_octal`, `uid`, `gid`, `mtime`, `ctime`.
- `sha256_hash`: Computed SHA-256 content digest (or `None` if unreadable).
- `is_symlink`, `symlink_target`: Detects and isolates symlink chains.
- `epistemic_status`: `OBSERVED`, `PERMISSION_RESTRICTED`, `SIZE_EXCEEDED`, or `UNKNOWN`.

### 3.2 `FileIntegrityScanner`
- Performs bounded inspection using `os.lstat` (never blindly follows symlinks).
- Computes SHA-256 for regular files $\le 10$ MB in 64 KB streaming chunks.
- **Unprivileged Safety:** When running without root permissions, files with restricted permissions (e.g. `/etc/shadow` mode 0640 `root:shadow`) record metadata with `sha256_hash=None` and `epistemic_status="PERMISSION_RESTRICTED"` rather than failing or hallucinating fake hashes!
- Enforces hard ceiling of `MAX_FILES_PER_SCAN = 2000` to prevent memory exhaustion.

### 3.3 `FilesystemPersistenceCollector`
- Subclasses `Collector` and integrates into LogIntel's `IngestionEngine`.
- **First Poll:** Records baseline states for all discovered HVT files (`is_baseline=True`).
- **Subsequent Polls (Delta Detection):**
  - **New file created in persistence vector:** Emits `FILE_PERSISTENCE_DROP` (`Severity.ALERT`).
  - **Content modified in privilege/config file:** Emits `FILE_INTEGRITY_MODIFY` (`Severity.CRITICAL` for `/etc/passwd` or `/etc/sudoers`, `Severity.ALERT` for others).
  - **File permissions/ownership modified (`chmod`/`chown`):** Emits `FILE_METADATA_MODIFY` (`Severity.WARNING`).
  - **Monitored persistence file deleted:** Emits `FILE_PERSISTENCE_REMOVE` (`Severity.NOTICE`).
- **Zero Churn Invariant:** Subsequent polling cycles with unchanged files emit **0 duplicate events**.
- Skips directory container content modification checks to prevent redundant parent directory events on child file additions.

## 4. Security & Epistemic Boundaries

1. **Anti-Hallucination Invariant:** Permission-restricted files report `epistemic_status="PERMISSION_RESTRICTED"` with `sha256_hash=None`. LogIntel never fabricates hash values.
2. **Symlink Escape Protection:** Does not recurse or traverse into external directories via symlinks; records symlink targets directly.
3. **Path Traversal Containment:** Normalizes target paths and prevents path traversal sequences (`..`).
4. **Metacharacter & Injection Resilience:** Filenames containing shell metacharacters or prompt injection payloads remain inert strings in forensic summaries.
5. **Resource Clamping:** Bounds maximum file hashing size to 10 MB and maximum scan entries to 2,000 files.
6. **Zero Schema Migrations:** All filesystem events and metadata map directly into existing canonical tables (`events`) and `metadata_json`, fully honoring the **No Migration 6** constraint.

## 5. API Endpoints

### 5.1 `GET /api/v1/investigations/filesystem/targets`
- **Parameters:**
  - `category`: Filter by `PERSISTENCE_CRON`, `ACCOUNT_PRIVILEGE`, etc.
  - `epistemic_status`: Filter by `OBSERVED`, `PERMISSION_RESTRICTED`, etc.
  - `limit`: Number of items (default 100, max 500).
- **Response:** List of currently tracked HVT files with current forensic states.

### 5.2 `GET /api/v1/investigations/filesystem/transitions`
- **Parameters:**
  - `transition_type`: Filter by `CREATED`, `MODIFIED`, `DELETED`, `METADATA_CHANGED`.
  - `limit`: Number of items (default 100).
- **Response:** Recorded file lifecycle transitions and audit details.
