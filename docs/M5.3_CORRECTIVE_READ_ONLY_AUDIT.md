## 2. AUDIT FINDINGS BY CORRECTIVE ITEM

### M53-C01: Investigation Intent Count (10 vs 11)
* **Specification Requirement:** 11 investigation intents (`SUMMARY`, `TIMELINE`, `ENTITY_ANALYSIS`, `EVIDENCE_EXPLANATION`, `ALERT_EXPLANATION`, `DETECTION_EXPLANATION`, `ATTACK_PATH_EXPLANATION`, `MITRE_EXPLANATION`, `HYPOTHESIS`, `EVIDENCE_GAP`, `NEXT_QUERY`).
* **Implementation Evidence:**
  - `apps/engine/src/logintel/ai/domain/intelligence.py` line 13: `InvestigationIntent` defines `SUMMARY`, `TIMELINE`, `ENTITY_ANALYSIS`, `EVIDENCE_EXPLANATION`, `ALERT_EXPLANATION`, `DETECTION_EXPLANATION`, `ATTACK_PATH_EXPLANATION`, `MITRE_EXPLANATION`, `HYPOTHESIS`, `EVIDENCE_GAP`, `NEXT_QUERY` (and `GENERAL` as fallback).
  - `apps/engine/src/logintel/ai/intelligence/classifier.py` line 15: `INTENT_PATTERNS` currently defines regex matchers for 10 intents. `EVIDENCE_EXPLANATION` is omitted from `INTENT_PATTERNS`.
* **Action Required:** Add `InvestigationIntent.EVIDENCE_EXPLANATION` pattern to `INTENT_PATTERNS` in `QuestionClassifier` and update all documentation from 10 to 11 investigation intents.

### M53-C02: Prompt-Injection Claim Qualification
* **Specification Requirement:** Differentiate model robustness from application containment. Do not claim XML envelope proves the model is immune to prompt injection.
* **Implementation Evidence:**
  - `M53-SEC-007` in `apps/engine/tests/test_ai_security_m53.py` verifies that injected prompt directives in log messages remain passive, unexecuted text in the XML payload and cannot execute privileged application functions or escape citation boundaries.
* **Action Required:** Qualify report language to clearly state that M5.3 verifies application-level containment of malicious telemetry (no tool calls, no arbitrary SQL, no shell commands, no citation bypass) without making unproven claims about model-level immunity.

### M53-C03: Database Preservation Language
* **Specification Requirement:** Replace "100% byte-for-byte fidelity" with "100% canonical content-hash equality" or "All baseline records reconciled with added=0, removed=0, changed=0 under the canonical SHA-256 row-hashing methodology."
* **Implementation Evidence:**
  - `scripts/reconcile_database_hashes.py` uses canonical JSON serialization (`separators=(",", ":")`, `ensure_ascii=False`, `sort_keys=True`) hashed with SHA-256 to prove zero record mutation.
* **Action Required:** Adjust report terminology to precisely describe canonical row-content hash equality and avoid claiming physical file byte identity.

### M53-C04: Conflict vs Temporal Anomaly
* **Specification Requirement:** Clearly separate `TEMPORAL_ANOMALY` (unusual sequence requiring analyst review) from true `EVIDENCE_CONFLICT` (mutually exclusive states reported for same entity/interval) and `VISIBILITY_GAP`.
* **Implementation Evidence:**
  - `retriever._detect_conflicts` in `retriever.py` identifies out-of-order authentication occurrences.
* **Action Required:** Refine semantic typing to distinguish `TEMPORAL_ANOMALY` from `STATE_CONTRADICTION` / `EVIDENCE_CONFLICT`.

### M53-C05: Telemetry Absence vs Visibility Gap
* **Specification Requirement:** Distinguish observed absence within available telemetry from a visibility gap (unconfigured source) or collection scope limitation.
* **Implementation Evidence:**
  - `retriever._audit_visibility_gaps` identifies missing `auditd` and network telemetry.
* **Action Required:** Ensure evidence gap classifications explicitly enforce that missing telemetry sources represent visibility blind spots, not proof of non-occurrence.

### M53-C06: Session Isolation Terminology
* **Specification Requirement:** Clarify that session isolation refers to in-memory, request-scoped ephemeral session dictionaries; zero persistent AI conversation history or database tables are created.
* **Implementation Evidence:**
  - `AIService._sessions` in `apps/engine/src/logintel/ai/service.py` is an in-memory Python dictionary keyed by `(user_id, incident_id, session_id)` with zero database persistence.
* **Action Required:** Clarify report wording to avoid implying persistent AI memory.

### M53-C07: SQLite user_version vs schema_migrations
* **Specification Requirement:** Explain why `PRAGMA user_version` is 0 while Migration count is 5.
* **Implementation Evidence:**
  - `apps/engine/src/logintel/storage/migrations.py` records applied migrations in the table `schema_migrations` (`version`, `name`, `applied_at`).
  - `SELECT version, name FROM schema_migrations` returns 5 applied migrations (1 through 5).
  - SQLite's `PRAGMA user_version` is unused by the application.
* **Action Required:** Document this explicitly in the verification report.

### M53-C08: Record Count Terminology
* **Specification Requirement:** Reconcile 141,069 canonical events vs 141,913 total core records across 8 tables.
* **Implementation Evidence:**
  - `events`: 141,069
  - `alerts`: 68
  - `detections`: 94
  - `incidents`: 143
  - `incident_entities`: 299
  - `incident_relationships`: 240
  - `investigation_notes`: 0
  - `investigation_notes_audit`: 0
  - Sum: 141,913 records.
* **Action Required:** Clarify distinction in documentation between canonical events (141,069) and total 8-table records (141,913).

### M53-C09: MITRE Verification Claim
* **Specification Requirement:** Bounded claim: M5.3 validates that citations resolve only to MITRE mappings already established in LogIntel M4 records; no external web validation is claimed.
* **Implementation Evidence:**
  - `ResponseParser` checks `[mitre:<id>]` against `context.citation_manifest`, which is populated exclusively from M4 `mitre_mappings`.
* **Action Required:** Qualify documentation language.
