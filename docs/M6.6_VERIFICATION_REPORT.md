# LOGINTEL — M6.6 IMPLEMENTATION & VERIFICATION REPORT

## 1. Executive Summary

Milestone **M6.6 — Systemd Unit Lifecycle & Security Kernel Telemetry** is the fifth implementation milestone of the **M6 (Advanced Linux Telemetry & Host Intelligence)** program. Following process execution (M6.2), identity continuity (M6.3), network sockets (M6.4), and filesystem persistence (M6.5), M6.6 introduces structured, deterministic, unprivileged telemetry for systemd unit lifecycles and Linux kernel security events.

Key accomplishments in M6.6:
1. **Systemd Lifecycle Parser:** Implemented `SystemdParser`, normalizing unit state transitions (`Starting`, `Started`, `Stopping`, `Stopped`, `Failed`, `Reloaded`) into structured canonical events (`SERVICE_STARTING`, `SERVICE_STARTED`, `SERVICE_STOPPING`, `SERVICE_STOPPED`, `SERVICE_FAILED`, `SERVICE_RELOADED`) across both syslog and journald JSON records.
2. **Kernel Security & Module Telemetry:** Enhanced `KernelParser` with detection for kernel module loading/unloading (`KERNEL_MODULE_LOAD`, `KERNEL_MODULE_UNLOAD`), out-of-tree kernel taints, untrusted module signature failures, and network interface promiscuous mode transitions (`KERNEL_SECURITY_ANOMALY`).
3. **Active Unit Tracker:** Implemented `SystemdUnitTracker`, providing safe unprivileged querying of active systemd units and granular inspection of unit properties (`MainPID`, `ExecMainStatus`, `ActiveState`, `Description`).
4. **REST API Endpoints:** Implemented authenticated endpoints `/investigations/systemd/units` and `/investigations/systemd/units/{unit_name}`.
5. **Zero Schema Migrations:** Preserves the **No Migration 6** constraint: all telemetry is stored in existing canonical tables and `metadata_json`.
6. **Comprehensive Verification:** 20 dedicated security assertions (`M66-SEC-001` through `M66-SEC-020`), 3 unit model tests, 7 parser/tracker tests, 5 kernel tests, 4 API tests, 1 determinism test over 10 repetitions (100% bit-for-bit identical), synthetic benchmark at 9,367 events/sec (0 KB memory leak), 44 frontend Vitest tests, and full backend regression suite (793 passing, 0 regressions).

## 3. Scope & Objectives

M6.6 delivers:
- Systemd unit lifecycle parsing (`Starting`, `Started`, `Stopping`, `Stopped`, `Failed`, `Reloaded`).
- Normalization into canonical event types (`SERVICE_STARTING`, `SERVICE_STARTED`, `SERVICE_FAILED`, etc.).
- Severity assignment (`Severity.ALERT` on `SERVICE_FAILED`, `Severity.NOTICE` on `SERVICE_STARTED`, etc.).
- Extraction of unit names, unit types, descriptions, exit codes, and PIDs.
- Kernel module loading (`KERNEL_MODULE_LOAD`) and unloading (`KERNEL_MODULE_UNLOAD`).
- Out-of-tree module taints and module signature verification failures (`Severity.ALERT`).
- Promiscuous mode device activation (`Severity.ALERT`).
- Active unit tracking via `SystemdUnitTracker`.
- REST API query routes (`/investigations/systemd/units`, `/investigations/systemd/units/{unit_name}`).

**Non-Goals Preserved:**
Strictly no systemctl unit modification commands (`systemctl start/stop/restart`), no kernel module loading/unloading actions, no container socket integration (deferred to M6.7), and strictly no Migration 6.

## 6. Epistemic Confidence Model

LogIntel strictly separates evidence from inference:
1. **`OBSERVED`:**
   - Active unit properties returned directly from systemd via `systemctl show`.
   - Log entries parsed from verified systemd and kernel streams.
2. **`INFERRED`:**
   - Unit name derived from service description string when explicit `_SYSTEMD_UNIT` attribute is missing.
3. **`UNKNOWN`:**
   - Transient or non-existent units (`load_state == "not-found"`).

## 7. Systemd Lifecycle Event Types

| Event Type | Action | Severity | Description |
| :--- | :--- | :--- | :--- |
| `SERVICE_STARTING` | `UNIT_STARTING` | `INFORMATIONAL` | Unit initialization begun |
| `SERVICE_STARTED` | `UNIT_STARTED` | `NOTICE` | Unit successfully activated |
| `SERVICE_STOPPING` | `UNIT_STOPPING` | `INFORMATIONAL` | Unit deactivation begun |
| `SERVICE_STOPPED` | `UNIT_STOPPED` | `NOTICE` | Unit successfully deactivated |
| `SERVICE_FAILED` | `UNIT_FAILED` | `ALERT` | Unit failed to start or crashed |
| `SERVICE_RELOADED` | `UNIT_RELOADED` | `NOTICE` | Unit configuration reloaded |

## 8. Kernel Security Event Types

| Event Type | Action | Severity | Description |
| :--- | :--- | :--- | :--- |
| `KERNEL_MODULE_LOAD` | `kernel_log` | `NOTICE` / `ALERT` | Kernel module loaded (ALERT if out-of-tree) |
| `KERNEL_MODULE_UNLOAD` | `kernel_log` | `NOTICE` | Kernel module unloaded |
| `KERNEL_SECURITY_ANOMALY` | `kernel_log` | `ALERT` | Module signature failure or promiscuous mode |

## 9. Security Protections & Threat Analysis

1. **Unprivileged Operation:** `SystemdUnitTracker` runs strictly unprivileged.
2. **Command Injection Containment:** Malicious unit names containing shell metacharacters (`; rm -rf /; $(whoami)`) remain inert text.
3. **Prompt Injection Safety:** Injection payloads inside service descriptions remain harmless strings.
4. **Subprocess Timeout Clamping:** All systemctl queries enforce bounded timeouts (2–5 seconds).
5. **No Traceback Leaks:** Unknown unit queries return clean HTTP 404 responses.

## 18. Documented Limitations

1. **Transient Units:** Services that start and exit within milliseconds between polling calls are captured via journald logs, but will not appear in point-in-time `list-units` snapshots.
2. **Kernel Dmesg Permission:** On hardened kernels with `dmesg_restrict=1`, unprivileged reads from dmesg are blocked; LogIntel reads kernel events via journald / syslog where access is permitted to the `adm` group.
3. **Historical Test Failures:** Exactly 6 pre-existing historical test failures in legacy AI corrective test suites remain documented and unchanged.
