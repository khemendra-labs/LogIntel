## 3. Scope Model Behavior & Semantics

### `InvestigationScope.target_hosts`
```python
target_hosts: List[str] = Field(default_factory=list)
```

- **Backward Compatibility:** Historical case records serialized without `target_hosts` deserialize into `target_hosts = []` without validation errors or schema adjustments.
- **Unspecified vs Empty Scope:** An empty list `[]` represents an **unspecified / dynamic host scope**. In this mode, participating hosts are resolved dynamically from evidence references, alerts, and events associated with the case. It does **not** imply that zero hosts exist.
- **Explicit Bounding:** A non-empty list explicitly focuses and bounds investigation analysis to the specified target hosts.
- **Sanitization & Normalization:**
  - Leading and trailing whitespace is stripped.
  - Non-printable ASCII control characters (`\x00-\x1f`, `\x7f`) are removed.
  - Identifiers are deduplicated case-insensitively, preserving the casing of the first occurrence.
  - Empty strings or whitespace-only strings are purged.
  - Single string inputs are coerced to single-element lists.
- **Validation Against Authorized Evidence:** Client-provided hosts are not trusted blindly. In `MultiHostInvestigationService`, hosts in `target_hosts` with zero observed telemetry or alerts are demarcated as `epistemic_status = UNKNOWN` with an explicit `TARGET_HOST_TELEMETRY_ABSENT` visibility gap.

## 4. API Contracts Added

All endpoints are mounted on `protected_router` with required `Authorization: Bearer <token>`.

### 1. `GET /api/v1/cases/{case_id}/hosts`
- **Purpose:** Retrieve the complete case-scoped multi-host dossier, inventory, lateral movement traces, cross-host entity continuity, and visibility gaps.
- **Response Model:** `CaseMultiHostDossier`
- **Status Codes:**
  - `200 OK`: Successful dossier assembly.
  - `401 / 403`: Unauthenticated or invalid engine token.
  - `404 Not Found`: `case_id` does not exist in `cases.db`.

### 2. `GET /api/v1/cases/{case_id}/hosts/lateral-traces`
- **Purpose:** Retrieve reconstructed cross-host movement traces for the case.
- **Response Model:** `List[MultiHostTrace]`
- **Status Codes:**
  - `200 OK`: Successful trace list.
  - `401 / 403`: Authentication failure.
  - `404 Not Found`: Case not found.

### 3. `GET /api/v1/cases/{case_id}/hosts/{host_id}/timeline`
- **Purpose:** Retrieve host-scoped unified timeline slice within case boundaries.
- **Parameters:** `limit` (1-500, default 100), `offset` (>=0, default 0), `time_start`, `time_end`.
- **Response Model:** `HostTimelineResponse`
- **Status Codes:**
  - `200 OK`: Successful timeline projection slice.
  - `401 / 403`: Authentication failure.
  - `404 Not Found`: Case not found OR host is not associated with the authorized case (cross-case isolation enforcement).

## 5. Security, Forensic Invariants & Epistemic Boundaries

1. **Database Immutability:** Authoritative forensic telemetry database `logintel.db` remained strictly read-only. Verified via SHA-256 pre- and post-operation digest assertion in `test_forensic_database_immutability`.
2. **Schema Migration Version:** Preserved at migration version **5**. Zero database migrations were added or modified.
3. **Case Authorization & Cross-Case Isolation:** Requesting a host timeline for an alien host or a host belonging exclusively to another case returns `404 Not Found` (`test_cross_case_isolation`), preventing resource leakage and cross-case enumeration.
4. **Epistemic Boundaries:**
   - Participating hosts with authoritative evidence are demarcated as `OBSERVED`.
   - Explicitly scoped target hosts with zero telemetry are demarcated as `UNKNOWN` with `TARGET_HOST_TELEMETRY_ABSENT`.
   - Missing telemetry is never interpreted as proof of event non-occurrence.
   - Hosts absent from `logintel.db:hosts` receive explicit `MISSING_HOST_CATALOG_ENTRY` visibility gaps.
5. **Determinism:** Multi-host dossier generation was validated across $N=10$ repeated runs on the identical case fixture (`test_multihost_determinism`), producing 100% stable sorting (hosts sorted by `host_id`, traces sorted by `(start_time, trace_id)`) and zero hash variance.
