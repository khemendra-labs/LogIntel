## 1. Executive Summary

Milestone M7.6 provides an end-to-end, evidence-grounded, reviewable reporting, packaging, and case handoff workflow for the LogIntel investigation platform. It formalizes the investigative synthesis pipeline:

$$\text{CASE} \longrightarrow \text{TIMELINE} \longrightarrow \text{COLLECTIONS} \longrightarrow \text{FINDINGS} \longrightarrow \text{HYPOTHESES} \longrightarrow \text{HUNTS} \longrightarrow \text{ASSESSMENT} \longrightarrow \text{REPORT} \longrightarrow \text{EVIDENCE PACKAGE} \longrightarrow \text{CASE HANDOFF}$$

M7.6 strictly preserves the platform's core epistemological invariant:

$$\text{AUTHORITATIVE EVIDENCE} \neq \text{ANALYST FINDING} \neq \text{HYPOTHESIS} \neq \text{ASSESSMENT} \neq \text{REPORT NARRATIVE} \neq \text{AI DRAFT CONTENT}$$

Key Architectural Properties Verified:
1. **Evidence Is Not Duplicated:** Reports and evidence packages reference authoritative telemetry through cryptographic identifiers, hashes, and canonical manifests rather than duplicating raw log tables.
2. **Authoritative Evidence Is Immutable:** Authoritative forensic telemetry in `logintel.db` remained 100% read-only throughout all reporting, packaging, and handoff operations.
3. **Epistemic State Remains Independent:** Non-negative epistemic boundaries (`OBSERVED`, `INFERRED`, `UNKNOWN`) are preserved. Absence of telemetry is explicitly distinguished from evidence of absence.
4. **Append-Only Immutability:** Reports are versioned strictly append-only. Modifying a report draft creates a new version row in SQLite; finalized reports are permanently frozen.
5. **Deterministic Provenance Manifests:** Every included evidence reference is cryptographically indexed with Blake2b digests under canonical field ordering.
6. **Deterministic Multi-Format Export:** JSON, CSV (with spreadsheet formula injection defanging), and Markdown exports produce byte-identical content and matching Blake2b fingerprints across repeated executions.
7. **Operational Case Handoff:** Analyst custody transfers are tracked with explicit identity and lifecycle states without automatically closing cases or asserting conclusions.

## 6. Report Architecture

The report model represents investigation state across 20 deterministic typed sections:
1. **Case Identification:** Identity, incident ID, title, status, version.
2. **Investigation Scope:** Scoped hosts, users, time window, and boundary notes.
3. **Executive Summary:** High-level narrative with explicit `content_origin` classification.
4. **Investigation Objective:** Primary investigative goal and triggering incident alerts.
5. **Evidence Sources:** Inspected telemetry sources and total event counts.
6. **Evidence Collections:** Integrated M7.3 logical evidence collections.
7. **Unified Timeline Summary:** Chronologically sorted event milestones from M7.2.
8. **Key Findings:** Integrated M7.4 analyst findings with epistemic classifications.
9. **Hypotheses:** Integrated M7.4 investigative hypotheses with status.
10. **Threat Hunting Activity:** Integrated M7.5 governed query executions and results.
11. **Evidence Correlation:** Correlated multi-attribute clusters from M5.9.
12. **Case Assessment:** Categorical assessment state and closure readiness from M5.11.
13. **Evidence Gaps:** Categorized missing telemetry preserving non-negative boundaries.
14. **Outstanding Questions:** Unresolved case investigative questions.
15. **Analyst Interpretation:** Analyst-authored analytical commentary.
16. **Conclusion:** Current forensic conclusion and ongoing monitoring requirements.
17. **Limitations:** Documented technical and operational investigative boundaries.
18. **Handoff Notes:** Operational instructions and recommended next actions.
19. **Provenance Manifest:** Cryptographic lineage table mapping included references.
20. **Report Metadata:** Report version, lifecycle status, timestamps, reviewer, Blake2b digest.

Lifecycle Transitions:
$$\text{DRAFT} \longrightarrow \text{REVIEW\_READY} \longrightarrow \text{FINALIZED} \longrightarrow \text{SUPERSEDED}$$
Every revision creates a new immutable SQLite version row (`PRIMARY KEY (case_id, report_id, version)`). Finalized versions cannot be updated.

## 7. Evidence Package Architecture

An evidence package is an autonomous, self-contained reference package indexing investigation artifacts:
- **Package Manifest:** `package_id`, `case_id`, `report_id`, `report_version`, `created_by`, `created_at`, `status`, `schema_version`, `generator_version`, `included_artifacts`, `source_reference_count`, `package_blake2b_digest`.
- **Report Snapshot:** Complete frozen snapshot of the referenced report version.
- **Artifacts Index:** Canonical JSON structures for collections, findings, hypotheses, hunts, timeline milestones, evidence gaps, outstanding questions, and the provenance manifest.
- **Deterministic Digest:** Blake2b-256 hash computed over canonical sorted JSON serialization.

---

## 8. Handoff Architecture

The case handoff workflow enables operational analyst-to-analyst custody transfer:
- **Handoff Packet:** `handoff_id`, `case_id`, `report_id`, `report_version`, `status`, `prepared_by`, `prepared_at`, `handed_off_to`, `acknowledged_by`, `return_reason`, scope summary, observed facts count, active hypotheses count, evidence gaps count, and recommended next actions.
- **Handoff Lifecycle:**
  $$\text{READY\_FOR\_HANDOFF} \longrightarrow \text{ACKNOWLEDGED} \quad \text{or} \quad \text{RETURNED\_FOR\_FOLLOWUP}$$
- **Invariant:** A handoff transfers operational custody. It never automatically closes the case, accepts findings, or asserts maliciousness.

## 9. AI Boundary

Local AI capabilities in M7.6 operate strictly within bounded advisory constraints:
- **Allowed Operations:** Drafting executive summaries, analyst interpretations, conclusions, and handoff notes based on existing case context.
- **Strict Prohibitions:** AI cannot finalize reports, close cases, accept hypotheses, modify authoritative telemetry, execute SQL, or run system commands.
- **Prompt Injection Defense:** Untrusted input strings (analyst notes, logs, guidance) are scanned and neutralized against instruction override tokens (`ignore previous instructions`, `system:`, script tags, shell commands).
- **Provenance Classification:** All AI-produced sections are explicitly labeled `content_origin = AI_GENERATED_DRAFT` and `advisory_only = True`.
