## 1. Executive Summary & Verification Verdict

An independent, strictly read-only post-remediation audit was conducted on Milestone 7.12 (M7.12.1 through M7.12.5). The audit verified the actual source code, repository diffs, database schemas, and test suites against the claims made in the corrective remediation and closure report.

### Audit Verdict: **VERIFIED WITH DOCUMENTED LIMITATIONS**

**Justification:**
All six defects identified during the initial audit (DEFECT-M712-001 through DEFECT-M712-006) have been remediated in the active source code, and all targeted regression tests pass cleanly (37/37 backend pytest tests, 76/76 frontend vitest tests, and desktop `tsc && vite build` passing with exit code 0). 

However, forensic rigor demands that several architectural subtleties and test harness characteristics be explicitly documented rather than glossed over:
1. **Provenance Hash Scope (M712-001):** The provenance fingerprint is deterministic, but its payload models case scope and topology components (participating hosts, lateral traces, continuities, and hop counts) rather than a complete cryptographic Merkle tree of intra-host event contents. Adding events to an already participating host without creating a new trace or host does not mutate the provenance hash.
2. **Threat Actor Identity Collision Risk (M712-002):** The actor resolution map (`ev_map`) indexes evidence items by bare string source ID (`sid = str(it.get("_source_id") or it.get("id"))`) without prepending the source type namespace. If an alert ID and an event ID collide, the latter overwrites the former. Furthermore, multiple conflicting actors in supporting evidence are resolved by first-match rather than conflict detection.
3. **Frontend Test Boundary (M712-003):** The frontend test suite tests exported safe timestamp helper functions and simulated string formatting. It does not mount `<InvestigationMultiHostWorkbench />` in a full React DOM testing environment, as `@testing-library/react` is not present in `apps/desktop`.
4. **Spanning Alert Temporal Boundary (M712-005):** The alert filter condition `(_is_in_scope_time(a_first) or _is_in_scope_time(a_last))` requires at least one endpoint to fall within the investigation window; alerts that completely engulf the window ($a_{first} < T_{start}$ and $a_{last} > T_{end}$) are excluded.
5. **Database Versioning Discrepancy (Phase 8):** The previous audit report incorrectly stated that `cases.db` had a schema migration version of 5. Source code inspection reveals `cases.db` is managed directly by `case_repo.py` via `CREATE TABLE IF NOT EXISTS` with `PRAGMA user_version = 0`, whereas `logintel.db` uses a 5-step migration table (`schema_migrations`). Neither database underwent schema mutations during remediation.

### DEFECT-M712-001: Deterministic Provenance Hash
- **Original Defect:** Provenance hash included wall-clock `now_iso` timestamp in `prov_payload`, causing non-deterministic root digests across calls.

- **Verification Evidence:**

- **Documented Limitation:** The hash represents a *scope, topology, and continuity fingerprint*. It does not include raw event payload hashes or individual evidence reference citation tags. Adding evidence items on existing participating hosts without introducing new hosts or traces does not alter `prov_payload`.

### DEFECT-M712-005: Case Scope Temporal Boundary Enforcement

      if not ts:
          return None
      try:
          dt = datetime.fromisoformat(ts.replace("Z", "+00:00"))
          if dt.tzinfo is None:
              dt = dt.replace(tzinfo=timezone.utc)
          return dt
      except Exception:

  scope_end_dt = _parse_ts_utc(scope_time_end)

  def _is_in_scope_time(ts: Optional[str]) -> bool:
      if not ts:
          return True
      dt = _parse_ts_utc(ts)
      if dt is None:

          if scope_time_start and clean_ts < scope_time_start.replace("Z", "+00:00"):
              return False
          if scope_time_end and clean_ts > scope_time_end.replace("Z", "+00:00"):
              return False
          return True
      if scope_start_dt and dt < scope_start_dt:
          return False
      if scope_end_dt and dt > scope_end_dt:
          return False
      return True

## 7. Outstanding Technical Risks and Architectural Observations

While all six reported defects are effectively resolved and verified, the following observations should be tracked for future architecture refinements:
1. **Intra-Host Evidence Provenance Sensitivity:** Because `prov_payload` hashes host identifiers and topological components, adding or removing evidence items on an already participating host without altering lateral traces or host inventory leaves the provenance hash unchanged. Future milestones could consider including an evidence Merkle digest in `prov_payload`.
2. **Actor Resolution Namespace:** In `reconstruction_engine.py`, prefixing evidence IDs with their domain (e.g. `f"{ref.source_type}:{ref.source_id}"`) in `ev_map` would eliminate the theoretical possibility of source ID collisions between different tables.
3. **Spanning Alert Interval Overlap:** Modifying the alert scope check from `(_is_in_scope_time(first) or _is_in_scope_time(last))` to an interval overlap formula ($last \ge start \land first \le end$) would allow alerts that span across the entire investigation window to be included.
4. **Desktop Component Integration Testing:** Installing `@testing-library/react` in future desktop milestones will allow automated verification of rendered JSX elements and user interaction rather than helper-only unit testing.
