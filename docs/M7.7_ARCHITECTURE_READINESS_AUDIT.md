# M7.7 ARCHITECTURE READINESS AUDIT

## Case Comparison, Campaign Correlation & Cross-Investigation Analysis

---

## 1. Executive Summary

Milestone **M7.7** introduces cross-investigation analysis to LogIntel, enabling analysts to compare two or more persistent investigations (Case A, Case B, and bounded additional cases) to detect deterministic, evidence-grounded relationships and campaign correlation candidates.

This capability is designed strictly under the local-first forensic trust model:
$$\text{AUTHORITATIVE EVIDENCE} \neq \text{ANALYST FINDING} \neq \text{HYPOTHESIS} \neq \text{ASSESSMENT} \neq \text{REPORT NARRATIVE} \neq \text{CAMPAIGN CORRELATION} \neq \text{AI ADVISORY}$$

$$\text{CORRELATION} \neq \text{PROOF} \neq \text{ATTRIBUTION} \neq \text{MALICIOUSNESS} \neq \text{CONFIDENCE SCORE} \neq \text{PROBABILITY} \neq \text{DETECTION}$$

The architectural audit establishes that:
1. **Authoritative Evidence Protection:** Authoritative event telemetry in `logintel.db` remains strictly read-only and immutable. Cross-case comparison operates purely over evidence pointers, extracted entities, timeline windows, findings, hypotheses, and threat hunt records.
2. **Epistemic Model Independence:** Epistemic states (`OBSERVED`, `INFERRED`, `UNKNOWN`) are strictly preserved. Shared attributes across cases (such as identical IPs or usernames) produce categorical correlation candidates (e.g., `SHARED_ENTITY`), but never automatically assert common threat actors or upgrade `UNKNOWN` / `INFERRED` into `OBSERVED`.
3. **No Numerical Confidence or Probabilities:** In strict accordance with LogIntel core principles, correlation outputs contain zero confidence scores, percentages, Bayesian probabilities, or risk numbers. All correlation bases and review statuses are categorical.
4. **Zero Schema Migrations:** All M7.7 comparison metadata, correlation candidates, review statuses, and export manifests can be safely persisted within existing `cases.db` tables (`case_evidence_references`, `case_finding_reviews`, `case_audit_log`) using structured JSON envelopes without introducing Migration 6. Database schema migrations remain frozen at **5**.
5. **Strict Case Isolation:** Multi-case comparison requires authenticated access to every participating case. Queries enforce explicit `case_id` checks, rejecting cross-case data leakage.
6. **Local Advisory AI:** AI assistance (via local loopback Ollama) is strictly advisory, bounded by XML encapsulation, denied access to arbitrary queries or state mutations, and cannot approve correlations or make attribution claims.

**Readiness Verdict:** `M7.7 ARCHITECTURE READY — IMPLEMENTATION MAY BEGIN`.

## 7. Campaign Correlation Architecture & Categorical Dimensions

### 7.1 Comparison Dimensions
1. **Entity Overlap:** Compares canonical entities across cases:
   - `HOST`: Hostnames, FQDNs
   - `USER`: Usernames, UIDs
   - `IP`: Source and destination IP addresses
   - `PROCESS`: Executable names, process paths
   - `COMMAND`: Executed command lines (exact and canonicalized)
   - `FILE`: File paths, file hashes
   - `SESSION`: Logon sessions, TTYs
   - `SERVICE`: Systemd services, daemon names
   - `SOCKET`: Listening/connected network sockets
   - `CONTAINER`: Container IDs, pod names
2. **Temporal Overlap:**
   - Case time windows: `[min_timestamp, max_timestamp]`
   - Overlap interval: `[max(start_A, start_B), min(end_A, end_B)]`
   - Window relationship: `TEMPORAL_OVERLAP`, `SEQUENTIAL_BEFORE`, `SEQUENTIAL_AFTER`, `DISTANT`
   - Temporal delta between case activities in seconds
3. **Finding Overlap:**
   - Overlap in finding titles, statements, finding types
   - Shared affected entities and MITRE mappings
   - Review states across findings
4. **Hypothesis Overlap:**
   - Comparative evaluation of active hypotheses across cases
   - Shared supporting vs contradicting evidence tags
   - Shared missing telemetry gaps
5. **Hunt Overlap:**
   - Comparison of executed query templates (`query_template_id`)
   - Matching hunt parameters (e.g. searching for the same suspicious binary or port)
   - Result overlap and entity pivots
6. **MITRE Overlap:**
   - Overlap in MITRE ATT&CK tactics, techniques, and sub-techniques.

### 7.2 Categorical Correlation Basis
Every generated candidate must explicitly declare its basis using categorical enums:
- `ENTITY_OVERLAP`
- `TEMPORAL_OVERLAP`
- `SEQUENCE_SIMILARITY`
- `TECHNIQUE_OVERLAP`
- `PROCESS_CONTINUITY`
- `NETWORK_CONTINUITY`
- `ACCOUNT_CONTINUITY`
- `FILE_CONTINUITY`
- `FINDING_OVERLAP`
- `HUNT_RESULT_OVERLAP`
- `MULTI_DIMENSIONAL_OVERLAP`

**Prohibited in M7.7:** No floating point confidence scores, Bayesian probabilities, risk percentages, or similarity scores.

## 8. Epistemic Model & Negative Evidence Semantics

### 8.1 Preserved Epistemic States
- `OBSERVED`: Authoritative forensic telemetry explicitly recorded the attribute in both cases.
- `INFERRED`: Derived analytical correlation or analyst deduction.
- `UNKNOWN`: Insufficient telemetry or unverified relationship.

**Invariant:** Correlation candidate generation or analyst review never transforms `INFERRED` or `UNKNOWN` into `OBSERVED`.

### 8.2 Corroboration vs Contradiction Nature
- `CORROBORATING`: Shared evidence supports the hypothesis of related activity.
- `CONTRADICTING`: Evidence contradicts the hypothesis of related activity (e.g., conflicting architecture, different target environments, temporal impossibility).
- `CONTEXTUAL`: Shared attribute is common infrastructure or shared utility (e.g., shared gateway IP, standard admin account).
- `TEMPORAL`: Proximity in time without direct entity linkage.
- `ENTITY_LINK`: Direct entity match without verified behavioral linkage.
- `SUPPORTING`: General supporting contextual data.
- `UNKNOWN`: Unassessed relationship nature.

### 8.3 Negative Evidence and Gaps
The engine explicitly distinguishes:
- `NO_EVENT_OBSERVED`: Logging was active, but no event was recorded.
- `SOURCE_UNAVAILABLE`: Telemetry source was not present on the host.
- `RULE_NOT_CONFIGURED`: Detection rule was disabled or unconfigured.
- `TELEMETRY_DROPPED`: Buffer overflow or ingestion drop detected.
- `UNKNOWN`: Unverifiable telemetry status.

**Rule:** Absence of telemetry is never presented as evidence of absence.

## 9. AI Boundary & Prompt Injection Containment

1. **Local Loopback Only:** Calls route exclusively to `http://127.0.0.1:11434/api/generate` (Ollama).
2. **Advisory Semantics:** All AI outputs carry `advisory_only=True` and `content_origin="AI_GENERATED"`.
3. **No Execution Privileges:** AI has no access to run database queries, execute shell commands, approve correlations, or finalize findings.
4. **Prompt Injection Containment:** Untrusted inputs (entity values, case notes, command lines) are enclosed in `<untrusted_investigation_evidence>` XML boundaries with explicit system instructions prohibiting execution of instructions embedded in data.

## 10. Persistence Strategy & Migration Decision

### 10.1 Schema Migration Decision: FROZEN AT 5
No new migration will be introduced. All M7.7 state will be persisted using existing schemas:
1. **Case Comparison Records:** Stored in `case_evidence_references` with:
   - `source_type = 'case_comparison'`
   - `reference_id = f"cmp-{comparison_id}"`
   - `analyst_annotation = json.dumps(comparison_payload)`
   - `role = 'CONTEXTUAL'`
   - `epistemic_status = 'OBSERVED'`
2. **Campaign Correlation Candidates:** Stored in `case_evidence_references` with:
   - `source_type = 'campaign_correlation'`
   - `reference_id = f"corr-{candidate_id}"`
   - `analyst_annotation = json.dumps(candidate_payload)`
   - `role = 'SUPPORTING'`
   - `epistemic_status = candidate.epistemic_status`
3. **Analyst Reviews:** Recorded via `case_finding_reviews` and `case_audit_log`.
4. **Audit Trail:** Recorded via `case_audit_log` with actions:
   - `COMPARISON_CREATED`
   - `COMPARISON_VIEWED`
   - `CORRELATION_REVIEWED`
   - `CORRELATION_ACCEPTED`
   - `CORRELATION_DISPUTED`
   - `CORRELATION_REJECTED`
   - `COMPARISON_EXPORTED`
   - `CAMPAIGN_CANDIDATE_CREATED`

## 13. API Route Design

Authenticated REST endpoints under `/api/v1/cases/{case_id}/comparison/`:
- `POST /cases/{case_id}/comparison`: Create and execute multi-case comparison
- `GET  /cases/{case_id}/comparison/{comparison_id}`: Retrieve existing comparison results
- `GET  /cases/{case_id}/comparison/{comparison_id}/entities`: Retrieve shared entity breakdown
- `GET  /cases/{case_id}/comparison/{comparison_id}/timeline`: Retrieve aligned comparative timeline
- `GET  /cases/{case_id}/comparison/{comparison_id}/correlations`: List correlation candidates
- `POST /cases/{case_id}/comparison/{comparison_id}/correlations/{candidate_id}/review`: Submit analyst review
- `POST /cases/{case_id}/comparison/{comparison_id}/ai-summary`: Request local advisory AI summary
- `GET  /cases/{case_id}/comparison/{comparison_id}/export`: Export deterministic JSON, CSV, or Markdown
