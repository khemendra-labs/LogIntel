## 4. INVESTIGATION WORKSPACE & LIFECYCLE

The session-scoped investigation workspace provides a deterministic state machine:

```text
                  ┌───────────────┐
                  │     OPEN      │
                  └───────┬───────┘
                          │
                          ▼
                  ┌───────────────┐
           ┌─────►│    ACTIVE     │◄─────┐
           │      └───┬───┬───┬───┘      │
           │          │   │   │          │
           │   ┌──────┘   │   └──────┐   │
           │   ▼          ▼          ▼   │
       ┌───────┴┐   ┌─────────┐   ┌──┴───┴┐
       │ PAUSED │   │ CLOSED  │   │ READY │
       └────────┘   └─────────┘   │  FOR  │
                                  │REVIEW │
                                  └───────┘
```

* **Validated State Transitions (`ALLOWED_INVESTIGATION_TRANSITIONS`):**
  * `OPEN` → `ACTIVE`, `CLOSED`
  * `ACTIVE` → `PAUSED`, `READY_FOR_REVIEW`, `CLOSED`
  * `PAUSED` → `ACTIVE`, `CLOSED`
  * `READY_FOR_REVIEW` → `ACTIVE`, `CLOSED`
  * `CLOSED` → `ACTIVE` (reopening requires explicit transition)
* **Audit Trail:** Every state change records `timestamp`, `actor`, `previous_state`, `new_state`, and `reason` in `state_history`.
* **Analyst Governance:** State transitions are restricted to authenticated local operator requests; AI completion cannot alter the investigation state.

## 6. HYPOTHESIS WORKFLOW

Hypotheses are modeled as first-class, analyst-owned constructs (`AnalystHypothesis`):
* **States:** `OPEN`, `SUPPORTED`, `WEAKENED`, `UNRESOLVED`, `REJECTED`.
* **Fields:** `hypothesis_id`, `statement`, `supporting_evidence_tags`, `contradicting_evidence_tags`, `evidence_gaps`, `analyst_assessment`.
* **AI Boundary:** AI is permitted only to propose hypothesis wording or suggest supporting/contradicting citation tags; the authenticated local operator retains sole authority over creation, status transitions, and final assessments.

## 7. EXPLAINABILITY & PROVENANCE LAYER

Every AI-assisted claim is explainable down to the underlying database records:
* **ClaimTrace Contract:** Resolves citation tags to source tables (`events`, `alerts`, `detections`, `incident_entities`, `mitre_tactics`) and returns the exact database row and timestamp.
* **Epistemic Separation:**
  * `OBSERVED`: Directly supported by authoritative forensic records.
  * `INFERRED`: Reasoned interpretation based on cited evidence.
  * `UNKNOWN`: Not established by available telemetry.
  * `HYPOTHESIS`: Potential explanation requiring analyst verification.

---

## 8. QUERY PROPOSAL & GOVERNED EXECUTION WORKFLOW

Threat-hunting queries proposed by AI undergo strict governance:
1. **Catalog Validation:** Proposals must match predefined allowlisted query templates (`query_failed_logins_by_user`, `query_process_lineage_by_parent`, etc.). Raw SQL from LLM completion is impossible.
2. **Local Operator Approval:** Query execution requires explicit POST request to `/query/execute` by an authenticated local operator.
3. **Deterministic Execution:** The engine executes parameterized queries and stages matching events into in-memory `evidence_candidates` without mutating authoritative detection tables.
