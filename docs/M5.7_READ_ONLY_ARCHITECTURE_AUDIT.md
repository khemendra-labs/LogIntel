## 7. Persistence Boundary

Preserve the strict three-tier architecture:
* **Tier 1 (`logintel.db`):** Protected authoritative forensic state. Strictly read-only for investigation workflows. Zero schema modifications.
* **Tier 2 (`cases.db`):** Persistent analyst state. Stores cases, hypotheses, evidence references, query history, immutable report drafts, audit log, and finding review decisions.
* **Tier 3 (AI Advisory):** Ephemeral reconstructed advisory context. Zero vector databases, zero embeddings, zero persistent AI memory.

## 8. Proposed M5.7 Additions

1. **Feature A — Investigation Dossier:** Assemble a comprehensive structured dossier containing Case Overview, Scope, Key Findings, Evidence Summary, Timeline, Entities, Correlations, Evidence Gaps, Hypotheses, Threat-Hunting Results, Attack Path, MITRE Techniques, Analyst Notes, AI Interpretation, Review State, and Provenance Manifest.
2. **Feature B — Key Findings with Review State:** Expand findings to include explicit severity, supporting/contradicting evidence citations, related timeline items, and review state (`UNREVIEWED`, `UNDER_REVIEW`, `ACCEPTED`, `REJECTED`, `NEEDS_MORE_EVIDENCE`).
3. **Feature C — Finding Review Workflow:** Provide `PATCH /cases/{case_id}/findings/{finding_id}/review` allowing analysts to accept/reject findings and record reviewer notes in `cases.db` and audit log without mutating forensic evidence.
4. **Feature D — Evidence Matrix:** Structured deterministic matrix for hypotheses detailing supporting evidence, contradicting evidence, evidence gaps, and explicit evidence-backed status (`SUPPORTED`, `WEAKLY_SUPPORTED`, `CONTRADICTED`, `INSUFFICIENT`, `UNRESOLVED`).
5. **Feature E — Evidence Gap Operationalization:** Convert telemetry gaps into structured next-action recommendations with analyst-controlled query execution.
6. **Feature F — Timeline Intelligence Refinement:** Enhance timeline items with source classification (`OBSERVED_EVENT`, `DETECTION`, `ALERT`, `INCIDENT`, `CORRELATION`, `FINDING`, `ANALYST_NOTE`, `HYPOTHESIS`, `THREAT_HUNT_RESULT`, `AI_INTERPRETATION`) and provenance integrity.
7. **Feature G — Threat-Hunt Result Integration:** Incorporate executed hunt results as first-class case evidence references with citation tags (`[hunt:...]`) and candidate findings.
8. **Feature H — Structured Case Briefing:** Deterministic briefing distinguishing observed evidence from derived correlations and AI interpretations.
9. **Feature I — Grounded AI Synthesis:** Advisory synthesis with strict prompt-injection boundary containment and structured schema adherence.
10. **Feature J — Report Generation:** Deterministic investigation report generation from the case dossier with immutable versioning.
11. **Feature K — Provenance Manifest:** Track per-claim/section source type, source ID, hash/reference, epistemic status, generator, and timestamp.
12. **Frontend Workbench:** Dedicated tabs/surfaces in desktop for Dossier, Review Workflow, Evidence Matrix, and Briefing.

## 10. Schema Decision

* **Authoritative DB (`logintel.db`):** **NO SCHEMA CHANGES.** Migration 6 remains strictly forbidden.
* **Case DB (`cases.db`):**
  - Add table `case_finding_reviews`:
    ```sql
    CREATE TABLE IF NOT EXISTS case_finding_reviews (
        review_id TEXT PRIMARY KEY,
        case_id INTEGER NOT NULL REFERENCES investigation_cases(case_id) ON DELETE CASCADE,
        finding_id TEXT NOT NULL,
        review_state TEXT NOT NULL DEFAULT 'UNREVIEWED',
        analyst_notes TEXT NOT NULL DEFAULT '',
        reviewed_by TEXT NOT NULL,
        reviewed_at TEXT NOT NULL,
        UNIQUE (case_id, finding_id)
    );
    CREATE INDEX IF NOT EXISTS idx_case_finding_reviews_case ON case_finding_reviews(case_id);
    ```
  - This preserves all existing tables and triggers, requires zero changes to `logintel.db`, and persists analyst review states without mutating forensic facts.

## 11. Security Boundary & Risks

* **AI Containment:** AI remains strictly advisory. Cannot execute commands, cannot execute arbitrary SQL, cannot accept findings automatically, cannot modify forensic rows.
* **Prompt Injection:** Untrusted evidence is demarcated in structural boundaries. AI output is parsed into strongly typed domain models.
* **Cross-Case Isolation:** All dossier, finding, review, matrix, briefing, and report operations enforce case ID validation.
* **Audit Trail:** Every finding review transition records an immutable entry in `case_audit_log`.
