## 1. EXECUTIVE SUMMARY

Milestone 5.2 introduces LogIntel's first operational, local-only AI runtime integration while strictly enforcing every M1–M5.1 forensic immutability and architectural invariant. 

The core architectural invariant established and proven across all operational modes, malformed outputs, and adversarial injections is:
```text
AI may READ authoritative evidence through approved context.
AI may NOT MODIFY authoritative evidence.
```

Under M5.2:
1. **Local-Only Runtime Boundary:** All AI model interactions connect strictly to loopback (`127.0.0.1` / `localhost`). Any attempt to configure non-loopback IPs (e.g. `0.0.0.0`, LAN IPs, public IPs, external hostnames) is rejected immediately at the configuration layer with `UnsafeProviderEndpoint`. There is zero external network dependency and zero cloud AI involvement.
2. **Untrusted Telemetry Framing:** All contextual log events and timeline items are treated as `UNTRUSTED_FORENSIC_DATA` and safely encapsulated in explicit XML delimiters (`<investigation_context>`, CDATA). The model possesses zero tool-calling capabilities, zero SQLite connections, zero filesystem write access, zero shell execution, and zero process spawning.
3. **Strict Structured Schema & Epistemic Enforcement:** Responses are parsed into validated Pydantic models requiring claims to bear valid epistemic statuses (`OBSERVED`, `INFERRED`, `UNKNOWN`). `OBSERVED` claims must cite authoritative evidence; `INFERRED` claims require both evidence and rationale; `UNKNOWN` claims strictly forbid citations.
4. **Context-Bounded Citation Manifest:** Model citations (e.g. `[event:...]`, `[alert:...]`) are validated strictly against the active `InvestigationContext.citation_manifest`. Any citation to events outside the active context—even if present in the global database—is rejected as an invalid cross-investigation citation.
5. **Zero Evidence Mutation & Zero Migration 6:** The database schema remains strictly at Version 5 (zero new migrations). Pre- and post-test cryptographic content hashes across all 141,069 events and related tables match with 0 added, 0 removed, and 0 changed records.
6. **Real Local Model Verification:** Verified end-to-end against a live, local Ollama daemon (`v0.35.0`) executing `qwen2.5:0.5b` (digest `a8b0c5157701`), generating schema-valid, non-authoritative analyst output with 100% citation compliance.

## 8. DETERMINISTIC REQUEST CONSTRUCTION

Requests are constructed by `RequestBuilder.build_prompt()` using the canonical serialized representation of `InvestigationContext`:
1. **System Prompt:** Explicitly instructs the model that it is an analytical assistant, log data is untrusted evidence (`UNTRUSTED_FORENSIC_DATA`), and tool execution is impossible.
2. **Evidence Framing:** The investigation context is wrapped in `<investigation_context>` tags with CDATA protection.
3. **Explicit Task:** A structured prompt demanding strict JSON adherence conforming to `StructuredAIResponse`.

## 9. MODEL RESPONSE CONTRACT

Responses are parsed into `StructuredAIResponse` conforming to:
```json
{
  "answer": "string",
  "claims": [
    {
      "text": "string",
      "epistemic_status": "OBSERVED | INFERRED | UNKNOWN",
      "evidence_refs": ["[event:evt-1]", "[alert:alt-1]"],
      "rationale": "string | null"
    }
  ],
  "suggested_queries": ["string"],
  "uncertainties": ["string"],
  "warnings": ["string"]
}
```

The output returned to the analyst carries non-authoritative metadata:
* `is_authoritative: False`
* `classification: "NON_AUTHORITATIVE_ANALYTICAL_OUTPUT"`
* `model_id`, `provider_id`, `request_id`, `generated_at`, `latency_ms`

---

## 10. CITATION VALIDATION

The citation validator cross-references every evidence tag in `claims[*].evidence_refs` against `InvestigationContext.citation_manifest`:
* Supported Citation Types: `[event:...]`, `[alert:...]`, `[detection:...]`, `[incident:...]`, `[entity:...]`, `[relationship:...]`, `[mitre:...]`.
* Cross-Investigation Isolation: If an event ID exists in the global database but is not part of the active incident's context manifest, it is rejected with `CrossInvestigationCitation`.
* Hallucinated Tags: Non-existent tags raise `InvalidCitation`.

---

## 11. EPISTEMIC VALIDATION

Claims are validated against M5.1 epistemic invariants:
* **OBSERVED:** Must have at least 1 valid evidence citation. Rationale is optional. (Violation raises `InvalidEpistemicClaim`).
* **INFERRED:** Must have at least 1 valid evidence citation AND a non-empty rationale explaining the inference. (Violation raises `InvalidEpistemicClaim`).
* **UNKNOWN:** Must NOT cite evidence (`evidence_refs` must be empty). (Violation raises `InvalidEpistemicClaim`).

## 27. KNOWN LIMITATIONS

1. **CPU Inference Latency:** On the test host (AMD Ryzen 5 4600H with no discrete GPU), generating 100–200 tokens takes ~30 seconds. On machines with dedicated GPU acceleration (CUDA/ROCm), latency is expected to be substantially lower (<2s).
2. **Model Context Window:** `qwen2.5:0.5b` is configured with a 2,048 token window. Large incidents with thousands of raw events require truncated context summaries (handled by M5.1 context token budgets).
3. **Structured Format Compliance:** Smaller models (<1B) occasionally require the system's markdown code-fence stripper to normalize output before JSON parsing. This is handled transparently by `ResponseParser`.
