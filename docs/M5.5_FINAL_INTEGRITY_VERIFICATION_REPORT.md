## 6. CASE DELETION / RETENTION SEMANTICS (C09)

### Invariant:
> **Investigation cases are never physically deleted. ARCHIVED is the retention state.**

### Enforcement Boundaries:
1. **API Layer:** No `DELETE` endpoint is exposed for cases in `apps/engine/src/logintel/api/routes/cases.py`. Case lifecycle transitions only allow `PATCH /api/v1/cases/{case_id}/status`.
2. **Service Layer:** `CaseService` exposes `transition_case_state(case_id, target_status, actor, reason)`. Valid states are `ACTIVE`, `SUSPENDED`, `CLOSED`, and `ARCHIVED`. No `delete_case` method exists.
3. **Repository Layer:** `CaseRepository` does not implement any SQL `DELETE FROM investigation_cases` query.
4. **Database Engine Layer (SQLite Trigger):** To safeguard against direct raw SQLite deletion and prevent foreign-key cascade removal of audit history, the following trigger is active on `cases.db`:
   ```sql
   CREATE TRIGGER IF NOT EXISTS trg_prevent_case_delete
   BEFORE DELETE ON investigation_cases
   BEGIN
       SELECT RAISE(ABORT, 'investigation_cases cannot be physically deleted; ARCHIVED is the retention state');
   END;
   ```
5. **Foreign-Key Cascade Audit Protection:** Although `case_audit_log` specifies `FOREIGN KEY (case_id) REFERENCES investigation_cases(case_id) ON DELETE CASCADE`, physical case deletion cannot execute because `trg_prevent_case_delete` unconditionally aborts the statement before the cascade can trigger. Direct SQL tests confirm:
   ```python
   with pytest.raises(sqlite3.DatabaseError) as exc:
       conn.execute("DELETE FROM investigation_cases WHERE case_id = ?", (case_id,))
   assert "cannot be physically deleted" in str(exc.value)
   ```
   Audit records for the case remain 100% intact.

## 8. REPORT VERSION IMMUTABILITY (C10)

Historical report drafts in `case_reports` are permanently preserved and immutable.

### Enforcement Boundaries:
- **Database Enforced:**
  ```sql
  CREATE TRIGGER IF NOT EXISTS trg_prevent_case_report_update
  BEFORE UPDATE ON case_reports
  BEGIN
      SELECT RAISE(ABORT, 'case_reports are immutable versioned records and cannot be updated');
  END;

  CREATE TRIGGER IF NOT EXISTS trg_prevent_case_report_delete
  BEFORE DELETE ON case_reports
  BEGIN
      SELECT RAISE(ABORT, 'case_reports are immutable versioned records and cannot be deleted');
  END;
  ```
- **Repository Enforced:** `CaseRepository.save_report_version()` queries `SELECT COALESCE(MAX(version), 0)` and executes an `INSERT INTO case_reports` with `version = next_version`. Existing rows are never updated.
- **Service Enforced:** `CaseService.draft_or_revise_report()` generates a new version object. Subsequent drafts leave prior versions unmodified.
- **API Enforced:** `POST /api/v1/cases/{case_id}/reports` writes a new version; `GET /api/v1/cases/{case_id}/reports/diff` provides historical version diffing.
- **AI Regeneration Safeguard:** When an analyst finalizes a report, `generated_by` is set to `ANALYST_AUTHORED` with `is_final = 1`. Any subsequent AI draft request produces version $N+1$ marked as `AI_GENERATED`, preserving the analyst's historical version byte-for-byte.
- **Test Verified:** `test_m55_cor_007` verifies that direct SQL `UPDATE` or `DELETE` on `case_reports WHERE version = 1` aborts with `DatabaseError: case_reports are immutable versioned records`.
