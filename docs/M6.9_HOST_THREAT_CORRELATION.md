# LOGINTEL — M6.9 ADVANCED DETECTION & THREAT CORRELATION ON HOST TELEMETRY

## 1. Overview & Architectural Mission

Milestone **M6.9 — Advanced Detection & Threat Correlation on Host Telemetry** synthesizes the full multi-layer host observability foundation established across M6.2 through M6.8 into an actionable, high-fidelity threat detection and attack-chain correlation engine.

Prior to M6.9, detection rules operated either as atomic syslog indicators or high-level network heuristics. M6.9 introduces:
- **Declarative Host Security Detection Rules (`rules/security/`):** Targeted detection covering in-memory process execution (`/dev/shm`, `memfd:`), reverse shells, persistence mechanisms (crontabs, systemd units, SSH keys), container escapes, unauthorized kernel module tampering, and adversary listeners.
- **MITRE ATT&CK Enterprise Mapping:** Explicit catalog mapping techniques across initial access, execution, persistence, privilege escalation, defense evasion, discovery, and command-and-control.
- **Host Threat Correlator (`HostThreatCorrelator`):** Deterministic temporal attack-sequence reconstruction linking discrete host indicators into unified cyber kill chains with quantitative threat scoring and epistemic confidence attribution.

## 2. Declarative Host Security Detection Rules

Eight production declarative detection rules were implemented in YAML format under `rules/security/` with `category: SECURITY`, preserving full compatibility with historical category query test assertions:

| Rule ID | Rule Name | Severity | MITRE Technique | Detection Trigger |
|:---|:---|:---:|:---:|:---|
| `sec.memory_execution` | Memory or Temporary Directory Process Execution | `ALERT` | `T1620` Reflective Code Loading | Execution from `/dev/shm`, `/tmp`, `/var/tmp`, `memfd:` |
| `sec.reverse_shell_socket` | Interactive Shell Outbound Socket Connection | `CRITICAL` | `T1071` Application Layer Protocol | Interactive shell (`bash`, `sh`, `zsh`, `python`) opening outbound network socket |
| `sec.cron_persistence_tamper` | Scheduled Task or Cron Persistence Modification | `WARNING` | `T1053.003` Cron | Creation or modification of crontabs in `/etc/cron*` or user spool |
| `sec.systemd_persistence_drop` | Systemd Service Persistence Unit Drop | `ALERT` | `T1543.002` Systemd Service | Modification or dropping of `.service` unit files in `/etc/systemd/system` |
| `sec.ssh_authorized_keys_tamper` | SSH Authorized Keys Backdoor Persistence | `ALERT` | `T1098.004` SSH Authorized Keys | Modification of `~/.ssh/authorized_keys` for persistence |
| `sec.container_escape_attempt` | Container Namespace Escape or Host Breakout Attempt | `CRITICAL` | `T1611` Escape to Host | Container breakout or host namespace join attempt (`nsenter`, unshare) |
| `sec.suspicious_listening_socket` | Suspicious Inbound Listening Socket Spawned | `WARNING` | `T1571` Non-Standard Port | Inbound socket opened on known adversary ports (4444, 1337, 31337) |
| `sec.kernel_module_tampering` | Kernel Module Insertion or Security Anomaly | `ALERT` | `T1547.006` Kernel Modules | Unauthorized kernel module loading or low-level kernel anomaly |

## 3. Host Threat Correlation Engine

### 3.1 Multi-Stage Kill-Chain Synthesis
The `HostThreatCorrelator` analyzes host telemetry events and operational alerts within a sliding window and identifies coordinated multi-stage attack scenarios:
1. **Container Breakout & Host Escape:** Container namespace breakout followed by root process execution and socket opening.
2. **Interactive Reverse Shell & External C2:** Process execution followed by interactive shell outbound socket connection to an external IP.
3. **Privilege Escalation & Persistence Establishment:** Sudo privilege elevation accompanied by crontab, systemd service, or SSH authorized keys modifications.
4. **In-Memory Execution & Defense Evasion:** Process execution from temporary/memory mounts paired with kernel security anomalies.
5. **Multi-Stage Host Takeover Campaign:** Multi-tactic intrusion covering initial access through command and control.

### 3.2 Quantitative Scoring & Epistemic Certainty
- **Threat Score (0.0 to 100.0):** Derived from base severity weights (Critical: 75, Alert: 55, Warning: 35, Notice: 20), combined with a stage diversity bonus ($+15$ per distinct MITRE tactic, up to $+30$).
- **Epistemic Confidence (0.0 to 1.0):** Distinguishes directly verified (`OBSERVED`) telemetry facts from reconstructed (`INFERRED`) states, penalizing unverified or speculative linkages.
- **Severity Escalation:** Automatically escalates multi-stage activity: Notice $\to$ Warning, Warning $\to$ Alert, Alert $\to$ Critical. Any active reverse shell or container breakout is immediately classified as `CRITICAL`.

## 4. REST API Endpoints

1. `GET /api/v1/detection/host-rules`
   - Returns full catalog of host security detection rules and associated MITRE ATT&CK techniques.
   - Enforces Bearer token authentication.
2. `POST /api/v1/correlation/host-threats/evaluate`
   - Evaluates host telemetry on-demand with optional client-supplied event payloads.
   - Returns structured `HostThreatAssessment` JSON.
3. `GET /api/v1/correlation/host-threats/{incident_id}`
   - Correlates evidence events and alerts for an incident, producing a comprehensive `HostThreatAssessment`.
   - Returns clean 404 if incident does not exist.
