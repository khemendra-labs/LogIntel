## 5. M5.6 GAP ANALYSIS & ARCHITECTURAL REQUIREMENTS

To achieve the M5.6 mission without turning into an autonomous SOC agent, the following architectural extensions are required:

1. **Investigation Findings Engine (`logintel.ai.intelligence.findings`):**
   - Must distinguish epistemic status: `OBSERVED`, `INFERRED`, `UNKNOWN`.
   - Every finding must carry a deterministic confidence basis (e.g. number of corroborating events/alerts, temporal correlation score).
   - Findings must be linked to case evidence, entities, alerts, and detections.
2. **Deterministic Correlation Engine (`logintel.ai.intelligence.correlator`):**
   - Multi-attribute correlation: `same host`, `same user`, `same src_ip`, `same dst_ip`, `same process`, `same executable`, `same command`, `same incident`, `same alert`, `same detection`, `temporal proximity`.
   - Must explicitly list reasons explaining *why* entities or items are correlated.
3. **Temporal Intelligence & Windows (`logintel.ai.intelligence.temporal`):**
   - Support `BEFORE`, `DURING`, and `AFTER` time-bounding relative to an anchor (alert, event, or pivot).
   - Distinguish `TEMPORAL_ANOMALY` (out-of-order sequence) from `STATE_CONTRADICTION` (mutually exclusive evidence).
4. **Evidence Corroboration & Gap Analysis (`logintel.ai.intelligence.gaps`):**
   - Corroboration categories: Primary, Supporting, Corroborating, Contradicting, Temporal, Entity-linked, Contextual.
   - Distinct missing states: "No supporting evidence found", "Searched but unavailable", "Telemetry source does not exist / uncollected".
   - Structured evidence gaps with recommended governed threat-hunting query proposals.
5. **Governed Threat-Hunting Workflow (`logintel.ai.intelligence.hunting`):**
   - Formal proposal -> validation -> preview -> approval -> execution -> candidate findings -> review lifecycle.
   - Typed query templates (whitelisted only; zero arbitrary or AI-generated executable SQL).
   - Explicit result states: `NO_MATCH`, `MATCHED`, `PARTIAL`, `UNAVAILABLE`, `INVALID`, `FAILED`.
6. **Entity-Centric Pivots (`logintel.ai.intelligence.pivots`):**
   - Unified pivot across entity types (`IP`, `USER`, `HOST`, `PROCESS`, `COMMAND`, `FILE`, `INCIDENT`, `ALERT`, `DETECTION`).
   - Case-scoped and cross-incident correlation view without duplicate storage in `cases.db`.
7. **Investigation Timeline Intelligence (`logintel.ai.intelligence.timeline`):**
   - Unified timeline view merging authoritative events, alerts, detections, incident milestones, analyst annotations, and derived correlations.
   - Strict visual and semantic provenance: never present AI interpretations as authoritative events.
8. **Hypothesis Evidence Support Analysis (`logintel.ai.intelligence.hypotheses`):**
   - Deterministic evidence matrix: `SUPPORTED BY CURRENT EVIDENCE`, `WEAKLY SUPPORTED`, `CONTRADICTED`, `INSUFFICIENT EVIDENCE`, `UNRESOLVED`.
   - Read-only analysis: Never modify analyst-owned hypothesis state automatically.
9. **Attack-Path & MITRE Integration:**
   - Integrate M4/M5 attack-path reconstruction, labeling steps as `OBSERVED`, `INFERRED`, or `UNAVAILABLE`.
   - Preserve 100% traceability to existing MITRE ATT&CK mappings.
10. **Stateless Local AI Investigation Synthesis:**
    - Assemble deterministic structured prompt context covering all above dimensions.
    - Contract: structured response model with application-level prompt-injection containment.
