## 4. C01 Audit Coverage Reconciliation

### Semantics
LogIntel explicitly distinguishes between operational telemetry states:
- `AUDIT RECORD AVAILABLE`: Raw record successfully read from the log.
- `AUDIT RULE CONFIGURED`: Kernel audit rule active for target syscalls (`execve`, `execveat`).
- `AUDIT RULE NOT CONFIGURED`: Telemetry source active but specific syscalls unmonitored.
- `AUDIT SOURCE AVAILABLE`: Log file exists and is accessible.
- `AUDIT SOURCE UNAVAILABLE`: Log file missing or unreadable.
- `TELEMETRY DROPPED`: Kernel audit backlog overflow or file truncation loss.

Under no circumstances does LogIntel equate `no EXECVE record` with `no process execution occurred`.

### Host Inspection Findings
- **Audit Daemon:** `auditd.service` active and running (`auditd 4.1.2`, PID 1490).
- **Log Path:** `/var/log/audit/audit.log` (File size: ~6.1 MB).
- **Permissions:** Root-owned, group `adm` (`-rw-r----- 1 root adm`).
- **Access Privilege:** LogIntel reads `/var/log/audit/audit.log` via group `adm` without requiring root privilege escalation.
- **Active Record Types:** Observed live `SYSCALL`, `PROCTITLE`, `SERVICE_START`, `SERVICE_STOP`, `AVC`, and `BPF` records.
- **Rule Coverage:** Default host rules record system services and authentication sessions; global `execve` auditing requires explicit administrator deployment (e.g. `auditctl -a always,exit -F arch=b64 -S execve -k exec_monitor`). This is explicitly documented as a deployment prerequisite.

### Definitive Coverage Statement
> **M6.2 provides deterministic ingestion and normalization of process and execution telemetry that is actually emitted by the host's configured Linux audit subsystem.**

## 5. C02 Data-Loss Claim Reconciliation

All unqualified "zero data loss" claims have been removed.

### Verified Ingestion Delivery
> **Deterministic audit-log ingestion with persistent offset and inode tracking was verified to preserve records without observed loss in the tested replay and real-host scenarios.**

### Kernel Delivery Limitation
LogIntel distinguishes between collector correctness and kernel delivery guarantees. If the Linux kernel's audit backlog queue overflows due to bursty execution (`auditctl -b` limit reached), records may be discarded by the kernel prior to reaching `/var/log/audit/audit.log`. LogIntel cannot prevent kernel backlog loss, but accurately ingests all records successfully delivered to disk.

## 7. C04 Ancestry Epistemic Reconciliation

Ancestry reconstruction in `ProcessAncestryResolver` enforces strict epistemic classifications:
- **`OBSERVED`:** Audit telemetry explicitly reports the PID/PPID relationship, and the parent process is matched to verified telemetry in the index.
- **`INFERRED`:** The parent-child relationship is contextually reconstructed across boundaries where direct telemetry is incomplete.
- **`UNKNOWN`:** Assigned when PPID is 0, parent event is unavailable, or process identity cannot be safely resolved.

LogIntel never manufactures a `SPAWNED` relationship from temporal proximity alone.

## 8. C05 Process Identity Terminology

Process identity is designated as:
> **Deterministic collision-resistant process identity**

Built via `build_process_identity(host, pid, timestamp, exe, audit_seq)`:
- Form: `proc:{host}:{pid}:{timestamp_iso}:{exe}:seq{audit_seq}`
- Verified: Successive PID reuse with differing timestamps, executables, or audit sequence numbers produces distinct identity strings. Truncated hash guarantees are qualified as collision-resistant rather than mathematically collision-free.

## 22. Known Limitations

The following limitations are explicitly documented and carried forward to M6.3+:
1. **Audit Rule Prerequisite:** Complete system-wide `execve` auditing requires explicit kernel audit rules configured by the administrator (e.g. `auditctl -a always,exit -F arch=b64 -S execve -k exec_monitor`). If unconfigured, LogIntel reports `AUDIT RECORD NOT AVAILABLE` rather than falsely concluding no executions occurred.
2. **Kernel Audit Backlog Buffer:** Under severe bursty execution, records dropped by kernel backlog overflow before reaching disk cannot be recovered by LogIntel.
3. **Container PID Mapping:** Audit records capture root host PID namespace IDs. Mapping to container-internal virtual PIDs is deferred to M6.5 container telemetry.
4. **Environment Variables:** `auditd` does not capture environment variables passed to `execve`; detailed environment forensics is deferred to future host instrumentation.
5. **Interactive Browser Verification:** Desktop frontend verified via automated tests and build, not live interactive browser sessions.
6. **Historical Database Dataset:** Historical row-level reconciliation unexecutable due to absence of authoritative historical baseline dataset.
