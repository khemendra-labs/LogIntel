## 1. Executive Summary

Milestone 5.8 implements **Evidence Relationship Intelligence, Investigation Graph & Correlation Explorer** for LogIntel.

The core objective achieved:
> **Turn LogIntel's existing forensic entities, relationships, detections, incidents, timeline information, findings, and evidence references into a deterministic, inspectable investigation graph whose every meaningful relationship can be traced back to authoritative evidence.**

### Key Forensic Principles Preserved:
1. **Source Wins:** The graph is a derived analytical representation, NOT the forensic source of truth. Authoritative telemetry in `logintel.db` remains untouched.
2. **Trust Hierarchy Preserved:** `RAW EVENT -> CANONICAL EVENT -> DETECTION -> ALERT -> INCIDENT -> ENTITY / RELATIONSHIP -> TIMELINE / GRAPH -> ATTACK PATH -> INVESTIGATION -> STRUCTURED EVIDENCE -> LOCAL AI`. Graph relationships never become authoritative merely by appearing in the UI.
3. **Evidence-Bound Edges:** Every meaningful relationship edge exposes its supporting canonical events, source references, timestamps, provenance, epistemic status, and corroboration quality.
4. **Epistemic Classification:** Clear separation of `OBSERVED` (authoritative telemetry), `INFERRED` (deterministic analytical logic), and `UNKNOWN` (cannot be established from available evidence).
5. **Zero Forensic DB Mutation:** Migration 6 was strictly avoided. Authoritative tables in `logintel.db` remain 100% identical (`added=0, removed=0, changed=0` across 141,069 canonical events and 141,913 baseline records).

## 4. Scope & Capability Inventory

The 18 capabilities delivered in M5.8:

1. **M58-01 (Graph Model):** Deterministic Investigation Graph domain model (`InvestigationGraphNode`, `InvestigationGraphEdge`, `InvestigationGraph`).
2. **M58-02 (Relationship Intelligence):** Explicit typed relationships (`AUTHENTICATED_TO`, `CONNECTED_TO`, `EXECUTED`, `SPAWNED`, `ACCESSED_FILE`, `LATERAL_MOVEMENT`, `CO_OCCURRED`, `HUNT_CANDIDATE`).
3. **M58-03 (Evidence Binding):** Every edge contains citations, event IDs, source references, and provenance.
4. **M58-04 (Relationship Classification):** Explicit `OBSERVED`, `INFERRED`, `UNKNOWN` tagging.
5. **M58-05 (Temporal Intelligence):** Chronological relationship sequence computation with delta seconds (`TemporalChain`, `TemporalChainStep`).
6. **M58-06 (Entity Pivot Explorer):** Deterministic entity-centric pivots retrieving linked nodes, edges, events, alerts, and findings (`EntityPivotGraph`).
7. **M58-07 (Strength Without Fake Scores):** Deterministic corroboration matrix (`DIRECT_OBSERVATION`, `CORROBORATED`, `SINGLE_SOURCE`, `CONTRADICTED`, `INSUFFICIENT_EVIDENCE`, `UNRESOLVED`) replacing arbitrary float confidence scores.
8. **M58-08 (Corroboration & Contradiction):** Evidence-based evaluation identifying multi-source confirmation and telemetry contradictions.
9. **M58-09 (Investigation Graph API):** 8 authenticated REST endpoints under `/api/v1/cases/{case_id}/graph/*`.
10. **M58-10 (Query Governance):** Hard server-side bounds (`max_nodes <= 500`, `max_depth <= 10`).
11. **M58-11 (Investigation Path Analysis):** Deterministic cycle-protected BFS path reconstruction (`InvestigationPath`).
12. **M58-12 (MITRE Integration):** ATT&CK tactic and technique IDs preserved with origin and epistemic status.
13. **M58-13 (Local AI Explanation):** Advisory-only relationship summaries with citation tags and non-authoritative tagging (`is_authoritative = False`).
14. **M58-14 (Prompt Injection Containment):** Hostile evidence inputs neutralized via application-level boundary enforcement.
15. **M58-15 (Investigation Graph UI):** Calm, forensic, evidence-oriented workbench (`InvestigationGraphExplorer.tsx`).
16. **M58-16 (Graph Interaction):** Node selection, edge inspection, filtering by epistemic status/relation type, pivot drill-down, and path search.
17. **M58-17 (Evidence Side Panel):** Structured drawer displaying relationship metadata, temporal bounds, corroboration quality, provenance, and supporting canonical events.
18. **M58-18 (Graph Export):** Evidence-preserving JSON and GraphML export formats.

## 7. API Inventory

All 8 M5.8 endpoints require valid Bearer token authentication, enforce case boundary isolation, apply typed query validation, and prohibit shell execution / raw SQL:

1. `GET /api/v1/cases/{case_id}/graph`: Query investigation graph with optional filters (`max_nodes`, `epistemic_status`, `relationship_type`, `entity_type`).
2. `GET /api/v1/cases/{case_id}/graph/nodes/{node_id}`: Inspect node detail and immediate 1-hop neighborhood.
3. `GET /api/v1/cases/{case_id}/graph/edges/{edge_id}/evidence`: Retrieve full structured supporting and contradicting evidence for an edge.
4. `GET /api/v1/cases/{case_id}/graph/pivots/{entity_type}/{entity_value}`: Execute deterministic entity-centric pivot across case telemetry.
5. `GET /api/v1/cases/{case_id}/graph/paths`: Reconstruct evidence-backed investigation path between source and target entities.
6. `GET /api/v1/cases/{case_id}/graph/temporal-chain`: Retrieve chronological relationship sequence with delta second calculations.
7. `POST /api/v1/cases/{case_id}/graph/explain`: Request local AI explanation of an edge or path (advisory only).
8. `GET /api/v1/cases/{case_id}/graph/export`: Export investigation graph in JSON or GraphML XML format.
