## 5. Phase 2: Alert Temporal Scope Semantics

### 5.1 Code Path Inspected:
[`apps/engine/src/logintel/multihost/service.py:195-217`](file:///home/khemendra-labs/LogIntel/apps/engine/src/logintel/multihost/service.py#L195-L217):

Where `_is_in_scope_time(ts)` evaluates:
```python

    return False
if scope_end_dt and dt > scope_end_dt:
    return False

```

### 5.2 Boundary Condition Analysis:

| Alert Interval vs Case Scope | Evaluation of `_is_in_scope_time(first)` | Evaluation of `_is_in_scope_time(last)` | Overall Filter Result | Expected Semantic | Assessment |
|---|---|---|---|---|---|
| Alert strictly before scope ($[06:00, 08:00]$ vs $[10:00, 12:00]$) | `False` | `False` | Excluded (`continue`) | Excluded | **CORRECT** |
| Alert strictly after scope ($[13:00, 15:00]$ vs $[10:00, 12:00]$) | `False` | `False` | Excluded (`continue`) | Excluded | **CORRECT** |
| Alert entirely inside scope ($[10:30, 11:30]$ vs $[10:00, 12:00]$) | `True` | `True` | Included | Included | **CORRECT** |
| Alert starts before, ends inside ($[08:00, 10:30]$ vs $[10:00, 12:00]$) | `False` | `True` | Included | Included | **CORRECT** |

### 5.3 Finding & Impact:
- **Classification:** **Confirmed Architectural Limitation / Edge-Case Defect** [INFERRED].
- **Impact:** Spanning alerts that encompass the entire investigation window are excluded from `host_alert_counts` and `host_evidence_tags`.
- **Closure Blocker Determination:** **Non-blocking for M7.12 closure**. In SOC operations, alerts are almost universally point-in-time detections or burst occurrences whose `first_seen` or `last_seen` fall within active threat windows.
- **Recommended Minimum Correction (for M7.13):**
  Replace line 210 with standard mathematical interval intersection:
  ```python

  l_dt = _parse_ts_utc(a_last) or f_dt
  f_dt = f_dt or l_dt
  ```

### 6.2 Forensic Analysis:
1. **Analyst Attribution Removal:** `case.owner` has been completely purged from the trace reconstruction logic. When evidence lacks an observed actor, `actor` defaults strictly to `"UNKNOWN"`.
2. **Namespace Collision Risk:**
   - In SQLite, `events.id` is `TEXT` while `alerts.id` is `INTEGER`.
   - `ev_map` indexes by `sid = str(...)` without prepending `source_type`.
   - If an event has `id="101"` and an alert has `id=101`, `ev_map["101"]` experiences a key collision, with the latter overwriting the former.
   - **Classification:** **Demonstrated Risk, Collision Not Observed** [INFERRED].
3. **Actor Conflict Resolution:**
   - If a transition edge has multiple supporting evidence references with conflicting usernames (e.g., `user_alice` on one reference and `user_bob` on another), the loop applies first-match (`break`).
   - The data model (`MultiHostTrace`) defines `actor: str` as a single scalar. It does not provide fields for ambiguous or conflicting actors.
   - **Classification:** **Confirmed Architectural Limitation** [OBSERVED].
4. **Recommended Future Improvement (for M7.13):**
   Index `ev_map` using namespaced keys: `f"{it.get('_source_type')}:{sid}"`.
