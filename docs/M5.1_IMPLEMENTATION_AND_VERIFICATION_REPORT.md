## 4. DOMAIN MODELS (`logintel.ai.domain`)

The domain contracts are partitioned into focused, non-circular modules:

1. **`epistemic.py`:**
   - `EpistemicStatus`: Typed enumeration (`OBSERVED`, `INFERRED`, `UNKNOWN`).
2. **`evidence.py`:**
   - `EvidenceType`: Supported authoritative categories (`event`, `detection`, `alert`, `incident`, `entity`, `relationship`, `step`, `mitre`, `note`).
   - `EvidenceTrustLevel`: Explicit trust marking (`UNTRUSTED_FORENSIC_DATA`, `VERIFIED_M4_METADATA`).
   - `EvidenceRef`: Immutable pointer (`evidence_type`, `evidence_id`, `canonical_key`).
   - `UntrustedTelemetryPayload`: Forensic event payload with automatic control character stripping (`\x00`, `\x08`).
3. **`citation.py`:**
   - `Citation`: Individual verified citation with canonical tag formatting (`[event:evt-101]`).
   - `CitationManifest`: Inventory of all valid tags in context; validates text output and separates valid citations from ungrounded hallucinated tags.
4. **`response.py`:**
   - `Claim`: Granular assertion linked to evidence refs; mandates `rationale` when status is `INFERRED`.
   - `CitationRef`: Verified citation extracted from response text.
   - `AIInvestigationResponse`: Complete typed response contract.
5. **`provider.py`:**
   - `ProviderCapabilities`: Declared token limits and schema support.
   - `ProviderResult`: Untrusted completion result with token and latency metadata.
   - `LocalAIProvider`: Abstract base class enforcing async `generate()` and `is_available()`.

- `citation_manifest`: Complete index of authoritative citation tags.

- `manifest.validate_citations(text)` parses bracketed tags and returns `(valid_citations, invalid_tags)`.

## 7. EPISTEMIC MODEL

LogIntel formally enforces three epistemic states:
1. `OBSERVED`: Statement directly supported by a cited `event`, `alert`, `detection`, `entity`, or `step`.
2. `INFERRED`: Analytical conclusion or deduction. The schema mandates that any `Claim` with status `INFERRED` must provide a non-empty `rationale` and supporting evidence references.
3. `UNKNOWN`: Statement acknowledging absence of evidence or unmonitored behavior. Must never be converted into an affirmative security assertion.

## 8. DETERMINISM GUARANTEE

The M5.1 context pipeline is 100% deterministic:
1. **Sorted Alerts:** Primary sort by severity weight (`CRITICAL` > `ALERT` > `WARNING` > `NOTICE` > `INFO`), secondary by `first_seen`, tertiary by `id`.
2. **Sorted Supporting Events:** Sorted by `timestamp ASC`, secondary by `id ASC`.
3. **Sorted Attack Path Steps:** Sorted by `step_number ASC`.
4. **Sorted Entities:** Sorted by `entity_type ASC`, secondary by `entity_key ASC`.
5. **Sorted Relationships:** Sorted by `id ASC`.
6. **Sorted Notes:** Sorted by `created_at ASC`, secondary by `id ASC`.
7. **Sorted MITRE Mappings:** Sorted by `tactic ASC`, secondary by `technique_id ASC`.
8. **Deterministic JSON:** `ContextSerializer.serialize_json()` enforces `sort_keys=True` and standard JSON escaping.

Repeated executions on identical database state yield **bit-for-bit identical JSON strings** (`test_context_assembly_determinism`).

## 9. CONTEXT PRIORITIZATION & TRUNCATION

When an incident exceeds budget limits, `InvestigationContextAssembler` enforces the priority hierarchy:

```text
Tier 1: Investigation Dossier Header  (Always retained)
Tier 2: Direct Supporting Evidence     (Events in detection_evidence)
Tier 3: Attack Path Topological Steps  (Reconstructed progression)
Tier 4: Correlated Security Alerts     (Ranked by severity)
Tier 5: Core Correlated Entities       (Incident graph entities)
Tier 6: Non-Tombstoned Analyst Notes   (Chronological active notes)
Tier 7: Contextual Telemetry Events    (Timeline background events)
```

### Truncation Disclosure
If evidence items exceed `ContextBudget` limits, they are omitted from lower priority tiers first, and `TruncationMetadata` records:
- `is_truncated = True`
- Exact counts (`omitted_events_count`, `omitted_alerts_count`, etc.)
- Human-readable justification strings explaining the omissions.

Authoritative supporting evidence is never silently dropped.

## 10. SERIALIZATION & PROMPT ENVELOPE

`ContextSerializer` provides two deterministic serialization formats:
1. **Deterministic JSON:** High-density, canonical JSON representation with sorted keys.
2. **Anti-Breakout XML Prompt Envelope:**
   - Encloses context within `<investigation_context version="1.0.0" id="...">`.
   - Wraps raw telemetry in `<untrusted_evidence_payloads>`.
   - Protects log payloads using CDATA sections (`<![CDATA[...]]>`).
   - Escapes any embedded `]]>` in log payloads to `]] >` to prevent CDATA escaping attacks.
