## 1. Executive Summary

Milestone **M7.12 (Multi-Host Investigation)** was designed to enable analysts to discover, correlate, and investigate security incidents spanning multiple enterprise host systems. Sub-milestone **M7.12.1** established the backend domain models and API foundation (`GET /api/v1/cases/{case_id}/hosts`, `/lateral-traces`, `/{host_id}/timeline`), and **M7.12.2** delivered the dedicated desktop Multi-Host Investigation Workbench ([`InvestigationMultiHostWorkbench.tsx`](file:///home/khemendra-labs/LogIntel/apps/desktop/src/features/InvestigationMultiHostWorkbench.tsx)), which subsequently underwent corrective closure for case-switching state isolation.

Prior audit documents identified an unresolved divergence regarding the intended scope of **M7.12.3**:
- **Option A (Comparative Timelines & Visual Topology):** Focuses on parallel multi-host timeline swimlanes, synchronized scrubbers, and interactive visual node-link lateral trace topologies.
- **Option B (Cross-Host Entity Correlation & Graph Pivoting):** Focuses on surfacing cross-host accounts and source IPs (`entity_continuity`), bidirectional pivoting between hosts/entities and the investigation graph, and deep host graph integration.

### Audit Verdict and Recommended Direction:
1. **Option B is recommended as the primary scope for M7.12.3:**  
   The backend foundation introduced in M7.12.1 *already computes* cross-host account continuity and multi-host source IP continuity via [`TemporalReconstructionEngine.detect_entity_continuity()`](file:///home/khemendra-labs/LogIntel/apps/engine/src/logintel/ai/temporal/reconstruction_engine.py#L640-L696) and serializes it in `CaseMultiHostDossier.entity_continuity`. However, the current desktop workbench completely ignores this field. Surfacing this pre-computed intelligence and connecting it to existing entity pivots ([`EntityPivotModal.tsx`](file:///home/khemendra-labs/LogIntel/apps/desktop/src/features/EntityPivotModal.tsx)) and investigation attack graphs ([`InvestigationGraphExplorer.tsx`](file:///home/khemendra-labs/LogIntel/apps/desktop/src/features/InvestigationGraphExplorer.tsx)) delivers immediate investigative capability with minimal risk and zero database schema changes.
2. **Option A is recommended to be sequenced as M7.12.4:**  
   Comparative multi-host timeline swimlanes and canvas-based visual trace rendering represent a substantial visualization task. Analysts must first know *which* hosts share accounts or exhibit lateral traces (Option B) before choosing which hosts to compare side-by-side in timeline swimlanes (Option A).
3. **Forensic and Architectural Boundaries Preserved:**  
   `logintel.db` remains strictly read-only, `cases.db` remains the authoritative state store, schema migrations remain frozen at version 5, case authorization and bearer-token requirements are enforced, and epistemic boundaries (`OBSERVED`, `INFERRED`, `UNKNOWN`) remain strictly preserved.

## 14. Forensic Integrity and Security Requirements

1. **Attribution Decoupling:** Shared entities across hosts (e.g. `svc_admin` or `192.168.1.50`) must never overwrite or blend original event telemetry. Each event must preserve its native `host` attribute.
2. **Epistemic Demarcation:** Correlating a shared account across hosts does NOT prove compromised credential replay without supporting authentication anomaly alerts. Status must be labeled `OBSERVED` for facts, `INFERRED` for reconstructed transitions.
3. **Case Boundary Isolation:** In-flight queries for `continuity` must be guarded by `activeCaseRef` to prevent cross-case data leakage.
4. **Deterministic Ordering:** Continuity records must be sorted deterministically by `(continuity_type, entity_key)` to ensure reproducible audit hashes.
