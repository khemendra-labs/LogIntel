## 5. FORENSIC PAYLOAD PRESERVATION (M5.1-CV-002)

### Standards-Safe CDATA Splitting & Anti-Escape Architecture
Under XML 1.0 specifications, `]]>` cannot appear literally inside a CDATA block. The previous naive workaround replaced `]]>` with `]] >`, permanently mutating log messages.
The corrected implementation (`encode_cdata_payload` / `decode_cdata_payload`):
1. **Standards-Safe Splitting:** Replaces `]]>` with `]]]]><![CDATA[>`. Standard XML parsers (`xml.etree.ElementTree`, `defusedxml`) parse the adjacent CDATA blocks into a single concatenated text node without modifying bytes.
2. **Transparent Control Character Preservation:** Characters forbidden in XML 1.0 (e.g. `\x00`, `\x08`, `\x1b`) or normalized by XML parsers (e.g. `\r`) are escaped as `\xHH` with `\` escaped as `\\`. On deserialization (`deserialize_xml_envelope`), exact byte-for-byte UTF-8 reconstruction occurs.
3. **JSON Parity:** Full byte-for-byte fidelity is maintained in both JSON and XML envelopes.

### Adversarial Payload Round-Trip Results
For all test payloads, `deserialize(serialize(payload)) == payload` and `recovered.encode("utf-8") == original.encode("utf-8")` held:

## 9. EPISTEMIC CONTRACT VERIFICATION

The 3-tier epistemic model (`OBSERVED`, `INFERRED`, `UNKNOWN`) is strictly enforced via Pydantic model validation on `Claim`:
- `OBSERVED`: Requires at least one authoritative evidence reference (`len(evidence_refs) >= 1`). Attempting to construct an `OBSERVED` claim with empty `evidence_refs` raises `ValueError`.
- `INFERRED`: Requires both supporting evidence references (`len(evidence_refs) >= 1`) AND a non-empty analytical `rationale`. Omission of either raises `ValueError`.
- `UNKNOWN`: Represents identified unknowns or investigative gaps. Attempting to assign evidence references to an `UNKNOWN` assertion raises `ValueError` to prevent hallucinated factuality.
