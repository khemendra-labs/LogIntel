## 1. Executive Summary & Mission

The mission of Milestone 5.8 is to implement:
> **M5.8 — Evidence Relationship Intelligence, Investigation Graph & Correlation Explorer**

M5.8 elevates LogIntel from an incident-centric workspace into a multi-dimensional, evidence-bound investigation graph. It enables security analysts to answer critical digital forensics and incident response (DFIR) questions:
- How are entities connected across cases and forensic evidence?
- Which events, detections, alerts, and findings belong to the same investigative chain?
- What precise evidence supports each relationship?
- Which relationships are directly observed versus deterministically inferred?
- Where are the evidence gaps or contradictions?
- How did an investigative chain evolve over time?
- Which entity pivots produce the strongest corroborating evidence?
- Can an analyst inspect the underlying evidence behind every single graph edge?

### Non-Negotiable Operating Principle
> **LogIntel must help an analyst connect evidence, not manufacture certainty.**

Every M5.8 capability must strictly adhere to the established trust hierarchy:
$$\text{RAW EVENT} \rightarrow \text{CANONICAL EVENT} \rightarrow \text{DETECTION} \rightarrow \text{ALERT} \rightarrow \text{INCIDENT} \rightarrow \text{ENTITY / RELATIONSHIP} \rightarrow \text{TIMELINE / GRAPH} \rightarrow \text{ATTACK PATH} \rightarrow \text{INVESTIGATION} \rightarrow \text{STRUCTURED EVIDENCE} \rightarrow \text{LOCAL AI}$$

Under no circumstances will graph relationships be treated as authoritative merely because they are rendered on a graph canvas. Graph representations are derived investigative models; the underlying forensic records remain the single source of truth:
$$\mathbf{Graph \neq Forensic\ Source\ of\ Truth \quad (\text{Source Wins})}$$

## 7. Proposed M5.8 Architecture

### 7.1 Investigation Graph Domain Schemas
A dedicated domain module will be created: `apps/engine/src/logintel/ai/domain/investigation_graph.py`.

```python
class GraphNodeType(str, Enum):
    # Domain entities
    HOST = "HOST"
    USER = "USER"
    IP = "IP"
    PROCESS = "PROCESS"
    COMMAND = "COMMAND"
    FILE = "FILE"
    SESSION = "SESSION"
    DOMAIN = "DOMAIN"
    CONTAINER = "CONTAINER"
    # Investigative context entities
    EVENT = "EVENT"
    DETECTION = "DETECTION"
    ALERT = "ALERT"
    INCIDENT = "INCIDENT"
    FINDING = "FINDING"

class RelationshipEpistemicStatus(str, Enum):
    OBSERVED = "OBSERVED"
    INFERRED = "INFERRED"
    UNKNOWN = "UNKNOWN"

class CorroborationStatus(str, Enum):
    DIRECT_EVIDENCE = "DIRECT_EVIDENCE"
    CORROBORATED = "CORROBORATED"        # Multi-source independent corroboration
    SINGLE_SOURCE = "SINGLE_SOURCE"      # Single evidence reference
    TEMPORALLY_ALIGNED = "TEMPORALLY_ALIGNED"
    CONTRADICTED = "CONTRADICTED"        # Conflicting evidence exists
    INSUFFICIENT_EVIDENCE = "INSUFFICIENT_EVIDENCE"
    UNRESOLVED = "UNRESOLVED"

class TemporalRelation(str, Enum):
    BEFORE = "BEFORE"
    DURING = "DURING"
    AFTER = "AFTER"
    OVERLAPS = "OVERLAPS"
    CO_OCCURRED = "CO_OCCURRED"
    SEQUENCE = "SEQUENCE"

class GraphEvidenceItem(BaseModel):
    reference_id: str
    source_type: str                     # event, alert, detection, hunt_query
    source_id: str
    source_hash: str                     # sha256:...
    citation_tag: str
    timestamp: Optional[str] = None
    summary: str
    epistemic_status: EpistemicStatus
    is_authoritative: bool
    role: str                            # primary, supporting, contradicting

class InvestigationGraphNode(BaseModel):
    node_id: str                         # e.g. "ent:user:attacker", "rec:alert:42"
    node_type: GraphNodeType
    display_label: str
    entity_key: Optional[str] = None
    is_authoritative: bool
    epistemic_status: EpistemicStatus
    source_reference: Optional[str] = None
    metadata: Dict[str, Any] = Field(default_factory=dict)
    first_seen: Optional[str] = None
    last_seen: Optional[str] = None
    degree: int = 0

class InvestigationGraphEdge(BaseModel):
    edge_id: str                         # e.g. "edge:user:attacker->host:srv-api-01:AUTHENTICATED_TO"
    source_node_id: str
    target_node_id: str
    relationship_type: str               # Canonical type
    epistemic_status: RelationshipEpistemicStatus
    is_authoritative: bool               # True if backed by persisted forensic records
    confidence: ConfidenceLevel
    corroboration_status: CorroborationStatus
    evidence_references: List[GraphEvidenceItem] = Field(default_factory=list)
    evidence_event_ids: List[str] = Field(default_factory=list)
    first_seen: Optional[str] = None
    last_seen: Optional[str] = None
    duration_seconds: Optional[float] = None
    temporal_relation: Optional[TemporalRelation] = None
    mitre_technique_id: Optional[str] = None
    mitre_tactic: Optional[str] = None
    description: str = ""
    provenance: str = ""

class InvestigationGraph(BaseModel):
    case_id: int
    incident_id: int
    nodes: List[InvestigationGraphNode]
    edges: List[InvestigationGraphEdge]
    total_nodes: int
    total_edges: int
    observed_edges_count: int
    inferred_edges_count: int
    corroborated_edges_count: int
    contradicted_edges_count: int
    generated_at: str
```

### 7.2 Bounded Traversal & Query Governance
To prevent denial of service and runaway memory consumption:
- `max_depth`: Default 2, clamped to $[1, 5]$.
- `max_nodes`: Default 50, clamped to $[1, 200]$.
- `max_edges`: Default 100, clamped to $[1, 500]$.
- Filtering parameters: `entity_type`, `relationship_type`, `epistemic_status`, `start_time`, `end_time`.
- Hard server-side enforcement: any requested limit exceeding the maximum is strictly clamped.

### 7.3 Investigation Path & Temporal Chain Models
- `InvestigationPath`: Bounded path reconstruction between `source_node_id` and `target_node_id`. Exposes ordered nodes, edges, cumulative evidence count, path nature (`OBSERVED`, `INFERRED`, `MIXED`), and temporal duration. Termed `INVESTIGATION_PATH` unless fully matching the specific attack path model.
- `TemporalChain`: Chronological sequence of relationship transitions and event linkages with exact delta-time annotations (e.g. `+12s`, `+3s`).

### 7.4 Dedicated API Surface Specification
Authenticated endpoints mounted under `/api/v1/cases/{case_id}/...`:

1. `GET /cases/{case_id}/graph` — Full bounded investigation graph (with pagination & filter clamps)
2. `GET /cases/{case_id}/graph/nodes/{node_id}` — Node detail with connected incident edges and evidence
3. `GET /cases/{case_id}/graph/edges/{edge_id}/evidence` — Deep evidence inspection for a specific graph edge
4. `GET /cases/{case_id}/graph/pivots/{entity_type}/{entity_value}` — Case-bounded entity pivot graph
5. `GET /cases/{case_id}/graph/paths` — Bounded path analysis between two entity nodes
6. `GET /cases/{case_id}/graph/temporal-chain` — Chronological transition chain of graph relationships
7. `POST /cases/{case_id}/graph/explain` — Local AI advisory explanation of a graph edge or path (advisory-only, citation-grounded)
8. `GET /cases/{case_id}/graph/export` — Evidence-preserving export in JSON or GraphML format

### 7.5 Local AI Advisory Layer
- Local Ollama runtime (`127.0.0.1:11434`) receives structured, deterministic JSON/XML context of the requested path or edge.
- Strictly prohibited:
  - Creating authoritative graph edges
  - Mutating SQLite tables (`logintel.db` or `cases.db`)
  - Executing ad-hoc SQL or shell commands
  - Promoting `INFERRED` $\rightarrow$ `OBSERVED`
- Application-level prompt injection containment verified across malicious telemetry inputs.
