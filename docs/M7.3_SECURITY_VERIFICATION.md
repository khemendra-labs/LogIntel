## 2. Forensic Invariant Verifications

1. **Evidence Collection ≠ Copy of Evidence (M73-SEC-016 & M73-SEC-017):**
   - Deleting a collection or removing an item removed only the organizational grouping link.
   - The authoritative evidence reference in `case_evidence_references` remained completely intact with unchanged `source_id`, `role`, and `added_at` timestamp.
   - Authoritative `logintel.db` maintained identical event counts and passed `PRAGMA integrity_check;` with `[('ok',)]`.
2. **Case Isolation & Zero Cross-Case Leakage (M73-SEC-004 & M73-SEC-014):**
   - Case 1 collections and workbench queries cannot view, reference, or export Case 2 items or collections.
   - Access attempts across case boundaries return deterministic HTTP 404 or empty sets without inferential metadata leaks.
3. **Audit Trail Immutability (M73-SEC-019):**
   - Every collection lifecycle action (`create_collection`, `add_item_to_collection`, `remove_item_from_collection`, `delete_collection`) logs an entry into the case audit trail.
   - Audit records are append-only; historical entries cannot be updated or purged via the API.
4. **Adversarial Content Inertness (M73-SEC-013 & M73-SEC-020):**
   - Payloads containing `<script>`, `DROP TABLE`, `$(whoami)`, and prompt-injection text were saved and retrieved verbatim without execution.
   - Static analysis of `apps/engine/src/logintel/collections/` verified zero instances of `subprocess`, `os.system`, `eval`, `exec`, or unparameterized raw SQL.
