### C05 & C06 — Finding Review Persistence, Case Deletion, and Triggers
* **Table Definition:** `cases.db.case_finding_reviews`
  * Columns: `review_id` (PK), `case_id` (FK), `finding_id`, `review_state`, `analyst_notes`, `reviewed_by`, `reviewed_at`.
  * Unique constraint: `UNIQUE (case_id, finding_id)`.
  * Index: `idx_case_finding_reviews_case` on `case_id`.
* **State Machine & Mutability:** Finding reviews transition through `UNREVIEWED -> UNDER_REVIEW -> ACCEPTED / REJECTED / NEEDS_MORE_EVIDENCE`. The review row in `case_finding_reviews` updates the current state to support fast lookups.
* **Audit Immutability:** Every review upsert automatically generates an audit record in `case_audit_log` (`action="FINDING_REVIEW_UPDATED"`). Triggers `trg_prevent_case_audit_update` and `trg_prevent_case_audit_delete` guarantee that audit history is append-only and immutable.
* **Deletion Semantics:** While the DDL specifies `ON DELETE CASCADE` for schema consistency, the database trigger `trg_prevent_case_delete` on `investigation_cases` aborts any DELETE attempt at runtime (`investigation_cases cannot be physically deleted; ARCHIVED is the retention state`). Therefore, case deletion cannot cascade because cases cannot be deleted.
* **Authoritative Boundary:** Reviews exist strictly within `cases.db`. Zero modifications occur in `logintel.db`.

### C07 — Evidence Matrix Logical Precedence
The evidence matrix evaluation logic in `apps/engine/src/logintel/ai/dossier/evidence_matrix_builder.py` enforces the following deterministic precedence:
1. **`CONTRADICTED` (Highest Precedence):** Triggered if any cited contradicting evidence reference resolves to `AVAILABLE` in authoritative forensic storage. Falsification overrides supporting evidence.
2. **`SUPPORTED`:** Triggered if resolved supporting references >= 1 and `len(evidence_gaps) == 0`.
3. **`WEAKLY_SUPPORTED`:** Triggered if resolved supporting references >= 1, but open evidence gaps remain unresolved.
4. **`INSUFFICIENT`:** Triggered if neither supporting nor contradicting evidence references were cited.
5. **`UNRESOLVED`:** Triggered if cited evidence references cannot be resolved against the forensic database (status is `MISSING` or `UNRESOLVED`).

*Property Verified:* The evaluation is pure functional Python; identical evidence sets deterministically yield identical matrix statuses without LLM interference.
