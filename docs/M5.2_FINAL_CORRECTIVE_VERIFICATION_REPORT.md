## 5. EFFECTIVE MODEL CONTEXT BUDGET [M5.2-CV-002]

### Resolution of Character vs Token Inconsistency
The apparent conflict between character counts (e.g. 32,768 characters) and model context tokens (e.g. 2,048 tokens for `qwen2.5:0.5b`) has been formally reconciled:
1. **Conservative Character-to-Token Ratio:** Set to `chars_per_token = 3.5` characters/token for structured security telemetry.
2. **Effective Budget Calculation:**
   * `model_context_tokens` = 2,048 tokens (configured in `ModelConfig`).
   * `reserved_output_tokens` = 512 tokens (`max_tokens`).
   * `max_input_tokens` = $2,048 - 512 = 1,536$ tokens.
   * `application_character_limit` = $1,536 \times 3.5 \approx 5,376$ characters.
3. **Safety Constraint:**
   $$\text{estimated\_input\_tokens} + \text{reserved\_output\_tokens} \le \text{context\_window\_tokens}$$

### Guard Implementation: `ModelContextBudgetGuard`
Implemented in [request.py](file:///home/khemendra-labs/LogIntel/apps/engine/src/logintel/ai/request.py):
* Validates request size before dispatching to the provider.
* If the estimated total tokens exceed the context window, raises `ContextBudgetExceeded` (error code `CONTEXT_BUDGET_EXCEEDED`).
* Passes `"num_ctx": model_config.context_window_tokens` in Ollama options to lock the daemon's active context window.

### Test Results:
* **M52-CV-002-A (Context below limit):** 1,200 chars (~343 tokens + 512 = 855 < 2,048) -> Accepted, headroom = 1,193 tokens. **PASS**
* **M52-CV-002-B (Context at effective boundary):** Exactly 1,000 tokens effective -> Accepted, headroom = 0. **PASS**
* **M52-CV-002-C (Context above effective boundary):** 1,001 tokens -> Raises `ContextBudgetExceeded`. **PASS**
* **M52-CV-002-D (Large investigation truncation):** Constrained budget truncates events and records omission in `ctx.truncation.truncation_reasons`. **PASS**
* **M52-CV-002-E (Output reservation preserved):** Reserved output tokens (512) strictly subtracted from context ceiling. **PASS**
