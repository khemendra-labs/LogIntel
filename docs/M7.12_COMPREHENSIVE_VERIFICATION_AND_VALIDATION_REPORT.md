## 1. Executive Summary

An exhaustive, adversarial, independent verification of Milestones **M7.12.1 through M7.12.5** was conducted across the LogIntel codebase. The audit bypassed previous milestone completion claims and implementation summaries, directly testing the actual source code, REST endpoints, database access layers, and desktop frontend components using isolated test fixtures, API clients, property-based input fuzzing, and production builds.

### Key Audit Findings:
1. **Core Capabilities Operational:**
   - Case-scoped host inventory discovery and multi-host dossier synthesis function across empty, single-host, and multi-host cases.
   - Cross-host entity continuity matching (`/hosts/continuity`) accurately groups shared accounts and IP addresses across disparate hosts.
   - Comparative multi-host timeline projection (`/hosts/timeline/comparative`) projects synchronized parallel lanes across participating hosts.
   - Visual SVG lateral trace topology correctly partitions hosts into topological ranks (sources, intermediaries, targets) and renders directed curves.
   - Dossier exporting generates structured JSON and Markdown investigation reports with SHA-256 digests.
   - Core forensic security invariants are maintained: `logintel.db` remained strictly read-only and bit-for-bit unmutated (SHA-256 verified), and database schema migration version remains frozen at 5.
2. **Defects Discovered (6 Actionable Defect Reports):**
   - **DEFECT-M712-001 (High):** Non-deterministic cryptographic provenance hash (`provenance_hash`). The hash payload includes the dynamic invocation timestamp (`now_iso`), causing identical evidence to yield different SHA-256 hashes across repeated calls.
   - **DEFECT-M712-002 (High):** Erroneous threat actor attribution. In `reconstruct_multi_host_traces`, `MultiHostTrace.actor` is hardcoded to `case.owner or "SecAnalyst-1"` (the investigating analyst) rather than the observed threat actor in telemetry (e.g. `svc_admin`), falsely accusing the analyst of malicious lateral movement.
   - **DEFECT-M712-003 (High):** Potential UI crash in Comparative Swimlanes. Line 1649 of `InvestigationMultiHostWorkbench.tsx` invokes `new Date(lane.last_seen || "").toISOString()`. When `last_seen` is null, JavaScript throws `RangeError: Invalid time value`, crashing the React render tree.
   - **DEFECT-M712-004 (Medium):** Event telemetry double-counting. Events cited in `case.evidence_references` and also present in `logintel.db:events` are counted twice in `CaseHostSummary.event_count`.
   - **DEFECT-M712-005 (Medium):** Temporal scope leakage. In `get_case_dossier`, telemetry event queries do not apply `case.scope.time_start` or `case.scope.time_end`, causing out-of-scope historical events to contaminate host event counts and `first_seen`/`last_seen` timestamps.
   - **DEFECT-M712-006 (Low):** Unescaped Markdown special characters and Python enum representation. Python `HostEpistemicStatus.UNKNOWN` string formatting appears in Markdown tables instead of `UNKNOWN`, and unescaped pipe characters `|` in host names break Markdown table columns.

## 15. Recommendations and Remediation Plan

Before Milestone M7.12 can be certified for release, the following corrections should be approved and applied:

1. **Remediate DEFECT-M712-001 (Provenance Hash Determinism):**
   - In `apps/engine/src/logintel/multihost/service.py` line 407, exclude `generated_at` from `prov_payload` (or compute provenance over immutable case evidence attributes).
   - Update `test_multihost_determinism` to explicitly assert `len(set(dossier.provenance_hash)) == 1` across N=10 runs.

2. **Remediate DEFECT-M712-002 (Lateral Trace Actor Attribution):**
   - In `apps/engine/src/logintel/ai/temporal/reconstruction_engine.py` line 622, extract actor from evidence transitions (`ht.from_entity` user, or transition evidence `item.get("username")`) instead of falling back unconditionally to `case.owner`.

3. **Remediate DEFECT-M712-003 (UI Date Null Safety in Comparative Swimlanes):**
   - In `InvestigationMultiHostWorkbench.tsx` line 1649, replace `new Date(lane.last_seen || "").toISOString()` with a safe helper that checks for truthy dates before converting to ISO string (e.g. `lane.last_seen ? new Date(lane.last_seen).toISOString().replace("T", " ") : "N/A"`).
