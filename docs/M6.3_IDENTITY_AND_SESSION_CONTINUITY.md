## 1. Overview & Architectural Mission

In traditional security monitoring, process execution telemetry often reports only the immediate effective user (`EUID: 0` or `root`). When an attacker or insider logs in under a legitimate account (e.g., `alice`) and escalates privileges via `sudo`, `su`, or setuid binaries to run reconnaissance tools, security analysts are confronted with root-level events devoid of human attribution.

Milestone M6.3 bridges this forensic gap by introducing **Multi-Source Identity Provenance and Session Continuity**:

```text
SSH LOGIN (10.10.10.25 -> alice)
         ↓
PAM SESSION OPEN (pts/1, session_id=42, auid=1001)
         ↓
PRIVILEGE TRANSITION (alice -> sudo su - -> root)
         ↓
ROOT PROCESS EXECUTION (nmap / tcpdump / bash under UID: 0)
         ↓
IdentityService & SessionContinuityResolver
         ↓
IdentityContinuityChain (Target: root | Origin: alice | AUID: 1001 | IP: 10.10.10.25 | Epistemic: OBSERVED)
```

By correlating events across **Linux Audit (`auditd`)**, **PAM Session Telemetry (`pam_unix`)**, **Sudo Logs**, and **SSH Authentication (`sshd`)**, LogIntel deterministically reconstructs the full human provenance of every executed process.

## 2. Linux Identity & Audit Architecture

### 2.1 The Kernel Audit ID (AUID / LoginUID)
Under the Linux kernel audit subsystem, processes maintain distinct identity attributes:
1. **Real UID (`uid`):** The credential of the process owner.
2. **Effective UID (`euid`):** The credential evaluated for access control decisions (0 for root).
3. **Saved UID (`suid`) & Filesystem UID (`fsuid`):** Used during privilege dropping and file access.
4. **Audit UID (`auid` or `loginuid`):** Set once by the login process (login, sshd, display manager) via `/proc/self/loginuid`. Once set in a process namespace, the kernel prevents unprivileged modification. Even if a user executes `sudo su -` or `su - root`, the `auid` remains invariant throughout the entire process tree.

### 2.2 Unset AUID & Daemon Attributions
Processes initiated by system startup, kernel threads, or background daemons (cron, systemd, timer units) run with an unset AUID (`4294967295`, `-1`, or `(none)`).
LogIntel strictly treats unset AUIDs as **non-interactive system context**:
- It **never** manufactures or hallucinates a human login identity for daemon executions.
- Epistemic status is set to `UNKNOWN`.
- The deterministic narrative clearly explains that execution occurred under an unauthenticated background service context.

## 3. Core Identity Components (`logintel.identity`)

### 3.1 `AuditIdentity`
Captures multi-tier Linux audit identity:
- `auid`, `uid`, `euid`, `suid`, `fsuid`, `username`, `login_username`.
- `is_unset_auid`: boolean flag automatically validated against `UNSET_AUID_VALUES` (`{"4294967295", "-1", "unset", "none"}`).
- `has_interactive_auid`: returns `True` only if AUID represents a genuine human login.
- `is_daemon_or_system`: returns `True` if execution occurred outside an interactive user context.

### 3.2 `SessionRecord` & `SessionState`
Tracks interactive sessions from inception to termination:
- Keyed by `(host, session_id)`.
- Records `auid`, `login_user`, `terminal`, `remote_ip`, `service`, `start_time`, `end_time`, and `state` (`ACTIVE` / `CLOSED`).
- Captures ordered list of `privilege_transitions` and set of spawned `process_pids`.

### 3.3 `SessionContinuityResolver`
Maintains in-memory session indexes across three dimensions:
1. `_sessions_by_id[host][session_id]`: Direct O(1) lookup.
2. `_sessions_by_auid[host][auid]`: Temporal lookup for processes retaining kernel AUID.
3. `_sessions_by_user[host][username]`: Fallback lookup for heuristic matching.

Key resolution logic:
- Ingests `register_session_start` from `AUDIT_SESSION_START`, `SESSION_OPEN`, and `AUTH_LOGIN_SUCCESS`.
- Ingests `register_session_end` from `AUDIT_SESSION_END`, `SESSION_CLOSE`, and `AUTH_LOGOUT`.
- Resolves process events via `resolve_identity_continuity(target_event, all_events)` into an `IdentityContinuityChain`.

### 3.4 `IdentityService`
Production service coordinating database queries and session reconstruction:
- Bounded temporal windowing: queries events within a 4-hour preceding window on the target host.
- Assembles chronological event streams and feeds the resolver.
- Exposes `get_identity_chain_for_event(event_id)` and `get_session_details(session_id, host)`.

## 5. Epistemic Confidence Boundaries

LogIntel adheres to strict epistemic certainty rules:

```text
                  ┌────────────────────────────────────────┐
                  │ Does event have matching session_id or │
                  │ verifiable kernel AUID on same host?   │
                  └──────────────────┬─────────────────────┘
                                     │
                    YES ─────────────┴───────────── NO
                     │                              │
                     ▼                              ▼
             [ OBSERVED ]              ┌──────────────────────────┐
      Direct cryptographic or          │ Does event have matching │
      kernel-level session binding     │ terminal & temporal window?
                                       └────────────┬─────────────┘
                                                    │
                                   YES ─────────────┴───────────── NO
                                    │                              │
                                    ▼                              ▼
                              [ INFERRED ]                    [ UNKNOWN ]
                       Heuristic temporal match          Daemon, unset AUID, or
                                                         unobserved session
```

1. **`OBSERVED`:**
   - Process metadata explicitly matches an active/historical `session_id` or kernel `auid` linked to a registered login.
   - Highest confidence forensic provenance.
2. **`INFERRED`:**
   - No direct session ID, but user and terminal match an active session on the host within a bounded temporal window.
3. **`UNKNOWN`:**
   - Unset AUID (`4294967295`), daemon executions, background services, or missing session history.
   - LogIntel explicitly reports `"No interactive session observed"`, avoiding manufactured certitude.

## 7. Security Guarantees & Safeguards

1. **AUID Immutability:** Kernel AUID strictly overrides untrusted environment variables (`$USER`) or application-level usernames.
2. **Daemon Isolation:** Daemon executions (`AUID: 4294967295`) are never attributed to interactive human users.
3. **Credential Masking:** Passwords and tokens in `sudo` commands and privileged executions are sanitized (`[MASKED]`) in command line and narrative representations, while preserving raw evidence unaltered in `raw_message`.
4. **Prompt & Shell Injection Inertness:** Shell metacharacters (`; && |`) and prompt injection strings remain strictly inert strings in identity narratives.
5. **Cross-Host Isolation:** Session IDs are strictly namespaced by host; identical session IDs across different machines can never cross-pollinate.
6. **Cycle & Depth Protection:** Privilege transition chains are capped at `max_depth = 32`, eliminating infinite loops and recursion denial-of-service.
7. **Zero Schema Migrations:** All identity and session telemetry is stored using existing `CanonicalEvent` models and `metadata_json`, fully adhering to the **No Migration 6** constraint.

## 8. API Endpoints

### 8.1 `GET /api/v1/investigations/events/{event_id}/identity-chain`
- **Authentication:** Bearer token required.
- **Response:** Complete `IdentityContinuityChain` with target process, origin user, session ID, privilege hops, epistemic status, and narrative.

### 8.2 `GET /api/v1/investigations/sessions/{session_id}`
- **Authentication:** Bearer token required.
- **Parameters:** `host` (optional filter).
- **Response:** Aggregated `SessionRecord` including all executed processes, executed commands, terminal metadata, remote IP, and privilege transitions.

### 8.3 `GET /api/v1/investigations/events/{event_id}/inspect`
- Automatically enriched with `identity_chain` metadata when inspecting process execution or privilege escalation events.
