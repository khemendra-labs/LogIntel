# LOGINTEL — M6.8 UNIFIED LINUX HOST GRAPH & ATTACK INTEGRATION

## 1. Overview & Architecture

Milestone **M6.8 — Host Telemetry Correlation & Attack Graph Integration** bridges low-level host telemetry with high-level incident attack graphs. It correlates:
- **Process Executions & Trees (M6.2):** `SPAWNED` causal edges, parent-child process chains, `build_process_identity` anti-PID-reuse logic.
- **Identity & Privilege Continuity (M6.3):** `EXECUTED` and `AUTHENTICATED_TO` edges, user attribution, privilege transitions.
- **Network Sockets & Flows (M6.4):** `CONNECTED_TO` and `BOUND_TO` edges connecting processes to remote IPs and local listening ports.
- **Filesystem Integrity & Persistence (M6.5):** `ACCESSED_FILE` and `MODIFIED_PERSISTENCE` edges targeting crontabs, systemd unit files, and SSH keys.
- **Systemd Service Lifecycle (M6.6):** `MANAGED_BY` edges tying processes to unit service definitions.
- **Container Isolation & Escapes (M6.7):** `CONTAINED_IN` and `ESCAPED_FROM` edges linking processes to container workload boundaries.

## 2. Graph Node & Edge Taxonomy

### Node Types (`HostNodeType`)
- `HOST`: Target Linux machine (`host:workstation-01`).
- `USER`: OS user identity (`user:alice`, `user:root`).
- `PROCESS`: Executed process (`process:host:pid:name`).
- `IP`: Remote network address (`ip:198.51.100.10`).
- `FILE`: Filesystem target or configuration (`file:/etc/shadow`).
- `SERVICE`: Systemd unit name (`service:ssh.service`).
- `CONTAINER`: Container runtime workload (`container:c7a8b9c0d1e2`).
- `SOCKET`: Listening port (`socket:tcp:4444`).
- `SESSION`: PAM or audit session (`session:1001`).

### Edge Types (`HostEdgeType`)
- `SPAWNED`: Parent process spawned child process (`PROCESS -> PROCESS`).
- `EXECUTED`: User executed process (`USER -> PROCESS`).
- `AUTHENTICATED_TO`: User authenticated to host or session (`USER -> HOST`).
- `CONNECTED_TO`: Process connected to remote network IP (`PROCESS -> IP`).
- `ACCESSED_FILE`: Process read/wrote sensitive file (`PROCESS -> FILE`).
- `MANAGED_BY`: Process managed by systemd service (`PROCESS -> SERVICE`).
- `CONTAINED_IN`: Process contained inside container (`PROCESS -> CONTAINER`).
- `ESCAPED_FROM`: Process broke out of container boundary (`PROCESS -> CONTAINER`).

## 3. Storage Safety & Database Preservation

To preserve existing database integrity and pass all test constraints across earlier milestones:
- Schema migrations remain at **exactly 5 migrations**.
- Extended node types (`CONTAINER`, `SERVICE`, `SOCKET`) map to `PROCESS` entities with custom metadata (`metadata["unified_node_type"]`) when persisted into the SQLite `incident_entities` table, satisfying SQLite `CHECK (entity_type IN ('HOST', 'USER', 'IP', 'PROCESS', 'COMMAND', 'FILE', 'SESSION'))`.
- Extended edge types (`CONTAINED_IN`, `MANAGED_BY`, `BOUND_TO`, `ESCAPED_FROM`) map safely to `CO_OCCURRED` or their closest canonical equivalent with full causal attributes in `metadata_json`.

## 4. API Endpoints

1. `GET /api/v1/investigations/hosts/{host}/graph`
   - Parameters: `limit` (default: 200, max: 1000)
   - Response: `UnifiedHostGraph` JSON containing all correlated nodes, edges, entity counts, and summary.
2. `GET /api/v1/investigations/{incident_id}/host-graph`
   - Response: `UnifiedHostGraph` JSON contextualized specifically for the incident's primary host and corroborated evidence events.
