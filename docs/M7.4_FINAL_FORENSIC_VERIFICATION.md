## 4. Key Architectural & Operational Implementations

### 4.1 Backend Engine (`apps/engine/src/logintel/findings/`)
- `models.py`:
  - `EpistemicStatus` (`OBSERVED`, `INFERRED`, `UNKNOWN`)
  - `ReviewStatus` (`UNREVIEWED`, `ACCEPTED`, `REJECTED`, `DISPUTED`)
  - `HypothesisStatusM74` (`OPEN`, `SUPPORTED`, `WEAKENED`, `DISPUTED`, `INCONCLUSIVE`, `REJECTED`)
  - `AnalystFinding`, `FindingVersion`, `FindingEvidenceReference`, `FindingContradiction`
  - `HypothesisEvaluationM74`, `CompetingHypothesesComparison`, `EvidenceGapM74`
- `service.py` (`FindingsWorkbenchService`):
  - CRUD operations for findings with automatic version history archiving.
  - Review state transitions preserving epistemic status.
  - Evidence reference association without duplicating event payloads.
  - Deletion semantics: disassociating evidence or deleting findings never deletes underlying evidence.
  - Competing hypothesis side-by-side comparison with categorical indicators and gap tallies.
  - Deterministic Blake2b JSON export with stable sorting.
- `api/routes.py`:
  - 18 authenticated REST endpoints mounted under `/api/v1/cases/{case_id}/findings/` and `/api/v1/cases/{case_id}/hypotheses/`.

### 4.2 Desktop Frontend (`apps/desktop/`)

  - Finding detail view with statement editor, version history timeline, attached evidence inspector, and review decision actions.
