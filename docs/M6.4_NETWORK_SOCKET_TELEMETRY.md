## 1. Overview & Architectural Mission

Prior to M6.4, LogIntel's network visibility was limited to passive syslog/kernel drops (UFW firewall block notifications) and inbound SSH remote IP authentication logs. The platform possessed zero visibility into:
1. Local listening network sockets opened by host processes (e.g. rogue listening ports, backdoor shells, web servers).
2. Outbound network sessions initiated by local processes (e.g. C2 beacons, reverse shells, unauthenticated data exfiltration).
3. Transient connection lifecycles (connection establishment, termination).

Milestone M6.4 delivers **deterministic, unprivileged Linux network and socket state telemetry** via procfs (`/proc/net/{tcp,tcp6,udp,udp6}` and `/proc/<pid>/fd/`):

```text
LINUX KERNEL SOCKET TABLES (/proc/net/tcp, tcp6, udp, udp6)
                         ↓
ProcNetReader (Decodes little-endian IPv4/IPv6 hex, ports, TCP states)
                         ↓
SocketProcessResolver (Scans /proc/<pid>/fd/ for socket:[inode] symlinks)
                         ↓
SocketStateCollector (Delta-detection across polls: LISTEN / ESTABLISHED / CLOSE)
                         ↓
M6.3 Identity Integration (Enriches with AUID, Login User, Session ID if present)
                         ↓
CanonicalEvent (NETWORK_SOCKET_LISTEN, NETWORK_SOCKET_CONNECTION, NETWORK_SOCKET_CLOSE)
                         ↓
Forensic Database (logintel.db events table, idempotent ingestion)
```

## 2. Kernel Procfs Telemetry Architecture

### 2.1 Unprivileged Privilege Architecture
Unlike packet capturing tools (`libpcap`, `tcpdump`) or eBPF programs that require `CAP_NET_RAW` or `CAP_SYS_ADMIN`, the Linux kernel exports `/proc/net/tcp`, `/proc/net/tcp6`, `/proc/net/udp`, and `/proc/net/udp6` with world-readable permissions (`-r--r--r-- 1 root root`).

LogIntel ingests complete socket tables with **ZERO root privilege escalation**.

### 2.2 Process Correlation & Epistemic Boundaries
In Linux procfs, sockets in `/proc/net/*` are identified by a 64-bit kernel inode number.
`SocketProcessResolver` correlates socket inodes to host processes:
1. For processes owned by the user (or all processes if running under appropriate capabilities), `/proc/<pid>/fd/` contains symlinks in the format `socket:[<inode>]`.
2. When an inode is matched, the process PID, comm, executable, and command line are attached, and epistemic certainty is recorded as **`OBSERVED`**.
3. When an inode cannot be mapped (e.g. root daemons like Postfix when running unprivileged, or transient sockets closed before the scan), LogIntel records the socket as **`UNKNOWN`** process attribution.
4. **LogIntel never hallucinates or manufactures process ownership for unmapped sockets.**

## 3. Core Network Components (`logintel.network`)

### 3.1 `SocketEntry` & `SocketState`
Captures detailed kernel socket telemetry:
- `protocol`: `TCP`, `UDP`, `TCP6`, `UDP6`.
- `local_address`, `local_port`: decoded standard IP and integer port.
- `remote_address`, `remote_port`: decoded endpoint IP and integer port.
- `state`: `ESTABLISHED`, `LISTEN`, `TIME_WAIT`, `CLOSE`, etc.
- `inode`, `uid`, `tx_queue`, `rx_queue`.
- `pid`, `process_name`, `process_executable`, `process_cmdline`, `process_user`.
- `epistemic_status`: `OBSERVED` or `UNKNOWN`.
- Helper predicates: `is_listening`, `is_established`, `is_loopback`, `is_outbound`.

### 3.2 `ProcNetReader`
Decodes kernel hex representations:
- **IPv4:** 8-character little-endian hex (e.g., `0100007F` $\rightarrow$ `127.0.0.1`).
- **IPv6:** 32-character hex structured as 4 little-endian 32-bit dwords (e.g., `00000000000000000000000001000000` $\rightarrow$ `::1`).
- **Port:** 16-bit big-endian hex (e.g., `01BB` $\rightarrow$ `443`).
- **Resource Clamping:** Bounds reading to `MAX_SOCKETS_PER_READ = 5000` entries per cycle.

### 3.3 `SocketProcessResolver`
- Caches inode-to-process lookups with a 2-second TTL.
- Extracts process details from `/proc/<pid>/{comm,exe,cmdline,status}`.
- Sanitizes command line credentials via `mask_credentials` (masks passwords, tokens, API keys, and `-u user:password` flags).

### 3.4 `SocketStateCollector`
- Monitors socket state transitions between polling cycles.
- **Initial Baseline Poll:** Records existing listening sockets as baseline events (`is_baseline=True`).
- **Delta Polls:** Emits events **only on transitions**:
  - `NETWORK_SOCKET_LISTEN`: Newly opened listening socket.
  - `NETWORK_SOCKET_CONNECTION`: Newly established connection (marked `Severity.NOTICE` if outbound).
  - `NETWORK_SOCKET_CLOSE`: Terminated established connection.
- Emits **zero duplicate events** if socket state is unchanged.

## 4. Integration with M6.3 Identity

When a socket event is associated with a verified PID, `SocketStateCollector` enriches the event via `SessionContinuityResolver`:
- Sets `actor.session_id` and `actor.username` to the authenticated human user.
- Attaches `metadata["login_user"]`, `metadata["auid"]`, and `metadata["session_id"]`.
- Directly connects outbound network sessions (e.g. `curl`, `nmap`) to the originating human login session and remote IP!

## 5. Security & Epistemic Safeguards

1. **Anti-Hallucination Invariant:** Unmapped sockets (e.g. root-owned daemons) remain `epistemic_status="UNKNOWN"` and `pid=None`. Process ownership is never guessed.
2. **Credential Sanitization:** Passwords and tokens in socket process command lines are masked (`[MASKED]`) in canonical fields while preserving raw socket evidence in `raw_message`.
3. **Loopback Isolation:** Loopback connections (`127.0.0.1`, `::1`) are strictly excluded from outbound classification (`is_outbound=False`).
4. **Path Traversal Containment:** Scans strictly inspect numeric PID directories in `/proc`, safely rejecting traversal characters (`..`).
5. **Prompt Injection Resilience:** Metacharacters and prompt injection payloads in process names remain inert strings.
6. **Zero Schema Migrations:** All network telemetry is stored using existing canonical event models and `metadata_json`, fully preserving the **No Migration 6** constraint.

## 6. API Endpoints

### 6.1 `GET /api/v1/investigations/network/sockets`
- **Parameters:**
  - `state`: Filter by state (`LISTEN`, `ESTABLISHED`, etc.).
  - `protocol`: Filter by protocol (`tcp`, `udp`, etc.).
  - `outbound_only`: Boolean flag for non-loopback established connections.
  - `limit`: Number of items (default 100, max 500).
- **Response:** Current socket snapshot including resolved processes and epistemic status.

### 6.2 `GET /api/v1/investigations/network/connections`
- Shortcut querying active established connections across the host.
