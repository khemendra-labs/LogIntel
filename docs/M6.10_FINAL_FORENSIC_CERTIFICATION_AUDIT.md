## 5. Functional Area Audits

### M6.1: Architecture & Telemetry Readiness
* Verified readiness of unprivileged Linux host telemetry pipelines.
* Enforces forensic immutability, epistemic certainty governance (`OBSERVED`, `INFERRED`, `UNKNOWN`), and loopback-only network isolation (`127.0.0.1`, `localhost`) for all local services and AI providers.

### M6.2: Process & Execution Telemetry via `auditd`
* **Audit Source Availability:** `/var/log/audit/audit.log` is readable unprivileged via membership in group `adm`.
* **Execution Telemetry Scope:**
  > **The audit source was available, but execution telemetry could not be treated as comprehensive because the required kernel audit execution rule was not configured on the tested host. The resulting state is UNKNOWN / RULE_NOT_CONFIGURED rather than evidence of absence.**
* **Process Identity:** Derived via `build_process_identity` in `ancestry.py` as `proc:host:pid:timestamp_iso:executable:seq{audit_seq}`. Certified as a **deterministic collision-resistant process identity token under the tested identity inputs**.
* **Process Ancestry:** `ProcessAncestryResolver` reconstructs parent-child execution hierarchies with cycle protection and depth clamping (32 generations). Missing PPID or PPID=0 is classified as `UNKNOWN`, never manufactured as `SPAWNED`.
* **Raw Forensic Evidence Preservation:**
  > **For the audited M6.2 raw audit-record ingestion path, byte-for-byte raw-message preservation was verified. Canonical, display, and AI representations may apply normalization or credential masking without altering the preserved raw forensic field.**

### M6.3: Identity, Session Continuity & Privilege
* **Continuity Scope:**
  > **Identity and session continuity are reconstructed from available audit, PAM, SSH, sudo, and related telemetry. Continuity is not asserted where required source records are unavailable, incomplete, or explicitly unset.**
* Unset/daemon sessions (`AUID=4294967295`) are recorded as system daemon executions without fabricating human attribution.
* Credential masking redacts sensitive authentication parameters in canonical and display models while preserving pristine raw strings in `raw_message`.

### M6.4: Linux Network & Socket State Telemetry via Procfs
* **Procfs Socket State:**
  > **Current/sample socket state observed through Procfs; transient socket lifecycle remains UNKNOWN where activity occurs between polling intervals.**
* `ProcNetReader` decodes `/proc/net/tcp` and `/proc/net/tcp6` tables with deterministic IPv4/IPv6 address hex parsing.
* `SocketProcessResolver` matches active socket inodes against `/proc/<pid>/fd/` entries (55 observed, 17 unmapped root/kernel marked `UNKNOWN`).
* **Documented Limitation:**
  > **Procfs polling does not provide packet-level visibility or guaranteed observation of transient socket lifecycles. eBPF socket monitoring is not implemented in M6.**

### M6.5: Filesystem & Persistence Telemetry (HVT Monitoring)
* **Scope & Clamping:**
  > **Filesystem telemetry is limited to configured high-value target paths and the configured hashing boundary. Missing, unreadable, symlink-protected, and size-clamped targets are explicitly represented rather than treated as clean or absent.**
* `FileIntegrityScanner` monitors critical persistence directories (`/etc/cron.*`, `/etc/systemd/system`, `/etc/pam.d`, `~/.ssh/authorized_keys`).
* Files exceeding the 10 MB size limit receive collection state `SIZE_EXCEEDED` with `sha256_hash = None` without reading into memory (`test_m65_sec_003_large_file_size_clamping`). Unreadable files (e.g., `/etc/shadow`) receive collection state `PERMISSION_RESTRICTED`.

### M6.6: Systemd Unit Lifecycle & Security Kernel Telemetry
* `SystemdUnitTracker` queries service lifecycles via `systemctl list-units` with graceful unprivileged fallback, detecting restart loops and failure cascades.
* `KernelCollector` deterministically parses module loads (`sys_module`), out-of-tree taint flags, signature verification failures, and promiscuous mode transitions from `/dev/kmsg` or syslog.
* `AppArmorParser` extracts AVC denial profile names, operations (`symlink`, `open`), requested masks, and target paths into structured canonical security denial events. `OBSERVED` state is assigned strictly when actual records are observed.

### M6.7: Container & Namespace Telemetry
* `NamespaceInspector` establishes baseline host namespace inodes from `/proc/1/ns/` (8 namespaces: `mnt`, `net`, `pid`, `ipc`, `uts`, `user`, `cgroup`, `time`). Namespace divergence in child processes indicates containerized execution unprivileged.
* **Docker Socket Limitation:** When `/var/run/docker.sock` is unreadable unprivileged, LogIntel reports `CONTAINER_TELEMETRY_UNAVAILABLE`.
  > **Unavailable Docker telemetry does not imply that no containers exist and does not imply that containers are safe.**

### M6.8: Unified Linux Host Graph & In-Memory Causal Synthesis
* `HostGraphBuilder` synthesizes host causal graphs dynamically in unprivileged memory. Nodes and edges carry explicit event IDs (`evidence_event_ids`) and discrete epistemic statuses (`OBSERVED`, `INFERRED`, `UNKNOWN`).
* **Migration 6 Final Reconciliation:**
  > **M6.8 did not introduce a persistent database schema migration. Host graph intelligence is synthesized on demand from existing canonical telemetry structures. Therefore Migration 6 is not required for M6.**
  The database invariant `len(MIGRATIONS) == 5` is strictly preserved. Migration 6 is **NOT REQUIRED BY THE FINAL M6 ARCHITECTURE**.

### M6.9: Advanced Detection & Threat Correlation on Host Telemetry
