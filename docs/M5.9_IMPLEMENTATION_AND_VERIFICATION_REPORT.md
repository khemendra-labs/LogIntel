# 1. EXECUTIVE SUMMARY & MISSION

Milestone M5.9 advances LogIntel from graph representation into **deterministic evidence correlation, multi-dimensional clustering, behavioral sequence analysis, and analyst decision support**.

While M5.8 answered:
> *"Show me how these entities are connected."*

M5.9 answers:
> *"Show me why these records are correlated, what concrete forensic evidence supports or contradicts that relationship, what evidence gaps exist, and what governed hunt query the analyst should consider next."*

### Key Guarantees Enforced:
1. **Evidence-First Provenance:** Every analytical cluster, behavioral sequence, and derived finding links to immutable forensic citations and 64-character hexadecimal SHA-256 digests generated and validated by the provenance mechanism.
2. **Deterministic Before Probabilistic:** Zero arbitrary confidence percentages (`confidence = 0.83`, `risk = 91`). Hypotheses are evaluated using categorical evidence support states (`SUPPORTED BY EVIDENCE`, `WEAKLY SUPPORTED`, `CONTRADICTED BY EVIDENCE`, `INSUFFICIENT EVIDENCE`).
3. **Epistemic Separation:** Strict demarcation between `OBSERVED`, `INFERRED`, and `UNKNOWN`. Finding review status (`ACCEPTED`, `DISPUTED`) is strictly decoupled from epistemic state.
4. **Analyst Control:** AI operates strictly as an advisory explanation mechanism (`is_authoritative = False`). No autonomous remediation, no arbitrary SQL execution, and no automatic mutation of authoritative data.
5. **Zero Migration 6:** M5.9 operates entirely using in-memory derived intelligence and existing `cases.db` structures. SQLite database schema version remains strictly at 5.

  `AdvancedEvidenceCorrelator` implementing deterministic multi-dimensional evidence clustering (auth, process, lateral/topology, temporal), chronological sequence alignment, gap detection, hypothesis evaluation, and entity workbench assembly.
- **`apps/engine/src/logintel/ai/case_service.py`**:

- **`apps/engine/src/logintel/storage/case_repo.py`**:
  Added `append_audit_log` helper to persist analytical finding derivations into the immutable `case_audit_log` table without schema modifications.
- **`apps/engine/src/logintel/api/routes.py`**:
  8 authenticated, case-isolated HTTP endpoints under `protected_router`:
  - `GET /cases/{case_id}/correlation/clusters`
  - `GET /cases/{case_id}/correlation/clusters/{cluster_id}`
  - `GET /cases/{case_id}/correlation/sequences`
  - `GET /cases/{case_id}/correlation/hypotheses/{hypothesis_id}/support`
  - `GET /cases/{case_id}/correlation/gaps`
  - `POST /cases/{case_id}/correlation/findings/generate`
  - `GET /cases/{case_id}/correlation/workbench/{entity_type}/{entity_value}`
  - `POST /cases/{case_id}/correlation/explain`

### Desktop Application Modules:
- **`apps/desktop/src/types/investigation.ts`**:
  TypeScript interfaces matching engine domain models.
- **`apps/desktop/src/lib/api.ts`**:
  Exported 8 authenticated client methods with automatic Bearer token propagation.
- **`apps/desktop/src/features/InvestigationCorrelationExplorer.tsx`**:
  High-density investigative UI providing 5 analytical views:
  - *Evidence Clusters View*: Cluster filters, correlation reasons with confidence bases, participating entities with pivot buttons, forensic citations, and local advisory AI explanations.

   Performance measurements were conducted on synthetic N=30 workstation datasets (120 entities, 80 relationships, 22 evidence records). They do not represent multi-million-event enterprise SIEM scale guarantees.

   As documented in M5.8, the runtime database at `~/.local/share/logintel/logintel.db` was reset by external environment package-maintenance prior to M5.8 closure. It remains unpopulated with historical raw events, while table schemas and detection rules (16) remain intact.

   Explanations generated by local Ollama instances depend on the local model weights and hardware availability. Application-level validation strictly ensures that AI explanations remain non-authoritative.
