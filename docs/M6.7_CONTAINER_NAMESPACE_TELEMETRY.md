## 1. Overview & Architectural Mission

Modern Linux production and investigation environments rely heavily on container runtimes (Docker, containerd, Podman, CRI-O). Until M6.7, LogIntel could not distinguish host processes from containerized processes, and container lifecycle transitions fell back to generic syslog lines.

**M6.7 introduces dual-layer container and namespace telemetry:**
1. **Procfs Namespace & Cgroup Inspection (`NamespaceInspector`):**
   - Unprivileged, non-invasive inspection of `/proc/<pid>/ns/*` against host baseline (PID 1).
   - Detects namespace isolation across `mnt`, `net`, `pid`, `ipc`, `uts`, `user`, and `cgroup`.
   - Extracts container IDs and runtime signatures from `/proc/<pid>/cgroup` (Docker, containerd, Podman, Kubernetes).
2. **Docker Socket Collector & Parser (`DockerSocketCollector`, `ContainerParser`):**
   - Interacts with `/var/run/docker.sock` via standard Python Unix domain sockets.
   - Gracefully handles permission boundaries (e.g. unprivileged user without `docker` group membership).
   - Normalizes container lifecycle actions (`create`, `start`, `stop`, `die`, `kill`, `destroy`, and breakout `escape`) into `CanonicalEvent` models.

```text
/proc/<pid>/ns & cgroup                    /var/run/docker.sock / daemon logs
             ↓                                               ↓
     NamespaceInspector                            DockerSocketCollector / ContainerParser
             ↓                                               ↓
ProcessNamespaceProfile (Isolated/Host)          ContainerLifecycleEvent (Start/Die/Escape)
             ↓                                               ↓
                    CanonicalEvent Generation & Forensic DB
```

## 2. Container Lifecycle & Security Event Types

| Event Type | Action | Severity | Description |
| :--- | :--- | :--- | :--- |
| `CONTAINER_LIFECYCLE_CREATE` | `CONTAINER_CREATED` | `INFORMATIONAL` | Container created |
| `CONTAINER_LIFECYCLE_START` | `CONTAINER_STARTED` | `NOTICE` / `ALERT` | Container started (`ALERT` if privileged) |
| `CONTAINER_LIFECYCLE_STOP` | `CONTAINER_STOPPED` | `INFORMATIONAL` | Container cleanly stopped |
| `CONTAINER_LIFECYCLE_DIE` | `CONTAINER_DIED` | `WARNING` | Container terminated / crashed |
| `CONTAINER_LIFECYCLE_KILL` | `CONTAINER_KILLED` | `WARNING` | Container killed via SIGKILL |
| `CONTAINER_LIFECYCLE_DESTROY`| `CONTAINER_DESTROYED` | `NOTICE` | Container removed/destroyed |
| `CONTAINER_SECURITY_ESCAPE_ATTEMPT` | `CONTAINER_ESCAPED` | `ALERT` | Potential container escape / breakout |

## 3. Epistemic Certainty Modeling

LogIntel strictly separates direct observations from inferences:
- **`OBSERVED`:**
  - Container ID and runtime extracted directly from cgroups or Docker socket inspection.
  - Host native process where all namespaces match host baseline.
- **`INFERRED`:**
  - Process displays kernel namespace divergence (`mnt`, `net`, `pid`), but no recognized container ID pattern is found in cgroups.
- **`UNKNOWN`:**
  - Process disappeared or access permissions prevented reading namespace inodes.

## 4. REST API Endpoints

1. `GET /api/v1/investigations/containers`:
   - Lists active containers discovered via Docker socket or procfs namespace grouping.
2. `GET /api/v1/investigations/containers/{container_id}`:
   - Detailed inspection of container configuration, image, privileges, and host PID mappings.
3. `GET /api/v1/investigations/processes/{pid}/namespace`:
   - Profiles kernel namespace divergence and container runtime binding for a host PID.
