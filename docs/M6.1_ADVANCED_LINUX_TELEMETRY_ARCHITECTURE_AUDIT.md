## 4. Current Architecture

```text
[Linux OS / Kernel / Daemons]
   │ (journalctl -o json, /var/log/auth.log, /var/log/syslog, /var/log/kern.log)
   ▼
[LogIntel Collectors] (JournalCollector, FileTailer)
   │ (RawRecord with byte_offset, inode, cursor)
   ▼
[Parser Registry] (SSHAuthParser, SudoParser, PAMSessionParser, UserManagementParser, KernelParser, GenericSyslogParser)
   │ (CanonicalEvent with SHA-256 event_fingerprint)
   ▼
[Ingestion Pipeline] (IngestionEngine: idempotent INSERT OR IGNORE)
   │
   ▼
[Authoritative Forensic Database] (logintel.db: events, detection_rules, alerts, incidents, incident_entities, incident_relationships)
   │
   ├──▶ [Deterministic Detection Engine] (YAML rules: Atomic, Threshold, Sequence)
   ├──▶ [Incident Correlation & Attack Graph] (Topological traversal, entity pivoting)
   └──▶ [Investigation Workspace & Cases DB] (cases.db: investigation_cases, hypotheses, assessments, briefings)
           │
           └──▶ [Local AI Advisory] (Loopback Ollama 127.0.0.1:11434, is_authoritative = false)
```

### Architectural Strengths
1. **Unidirectional Trust:** Analysis flows strictly downward from authoritative telemetry to mutable investigation workspaces and transient AI advisories.
2. **Idempotent Ingestion:** The `events` table uses `idx_events_fingerprint` (`UNIQUE INDEX`) ensuring identical raw log replays never corrupt forensic counts.
3. **Decoupled Workspaces:** `cases.db` is completely separate from `logintel.db`.

### Architectural Bottlenecks
1. **Polling Architecture:** `FileTailer` and `JournalCollector` operate on a synchronous polling loop (`poll_interval_seconds = 2.0`), which introduces latency and CPU wakeups.
2. **Synchronous Parser Registry:** Parsers execute linearly in Python (`BaseParser.can_parse`) without regex pre-compilation caching across threads.
3. **No Event Streaming Bus:** Ingestion directly batches SQLite transactions (`batch_size = 500`), creating write contention if multiple high-frequency collectors write simultaneously.

## 7. Process & Execution Readiness

### Current State
LogIntel currently observes process execution **only** when an interactive user invokes a privileged command via `sudo` (`SUDO_COMMAND` in `sudo.py`), or when AppArmor records a violation (`comm=`, `pid=` in `kernel.py`). General execution (`execve`, `fork`, `clone`) by unprivileged users, automated cron jobs, or compromised background daemons is **completely invisible**.

### Telemetry Gap Analysis
- **Missing Fields:** `ppid` is rarely populated from text logs; `euid`/`egid` are missing; process working directory (`cwd`) is missing; exit codes and process durations are missing.
- **PID Reuse Vulnerability:** Linux kernel PIDs cycle continuously (default `pid_max = 4194304` or `32768`). Without recording process start time (`start_time` or monotonic tick count), correlation by PID alone results in false graph links across long timeframes.
- **Epistemic Classification:**
  - `OBSERVED`: Explicit `execve` records with start time and binary hash.
  - `INFERRED`: Parent-child relationship reconstructed from asynchronous log lines.
  - `UNKNOWN`: Subprocesses spawned inside short-lived subshells not captured by logging.

### Recommended Acquisition Mechanism
- **Primary:** `auditd` syscall auditing for `execve` / `execveat` via `/var/log/audit/audit.log` (type `SYSCALL` + `EXECVE` + `PROCTITLE`).
- **Secondary (Periodic State):** `/proc` snapshotting for running processes and ancestry verification.

## 8. Authentication & Identity Readiness

### Current State
High maturity for standard SSH and PAM sessions:
- `SSHAuthParser` extracts `username`, `src_ip`, `src_port`, `auth_method` (password/publickey), and outcome.
- `PAMSessionParser` extracts session open/close, `service`, and `username`.
- Identity continuity: Tracked via `username` and `src_ip`.

## 10. Network & Socket Readiness

### Current State
Current network telemetry is limited to:
1. External inbound connection attempts blocked by UFW in kernel messages (`[UFW BLOCK] SRC=... DST=... PROTO=... DPT=...`).
2. SSH remote client endpoints (`src_ip`, `src_port`).

### Telemetry Gap Analysis
- **Outbound Connections:** LogIntel has zero visibility into outbound HTTP/HTTPS connections, C2 beacons, or DNS queries initiated by local processes.
- **Listening Sockets:** LogIntel cannot observe which local ports are bound or listening.
- **Process Association:** UFW kernel logs do not provide process names or PIDs for blocked packets.

### Acquisition Feasibility
- Local inspection confirms `/proc/net/tcp` and `/proc/net/tcp6` are readable without root privileges.
- Sockets can be decoded to obtain local/remote addresses, state (e.g. `0A` = `LISTEN`, `01` = `ESTABLISHED`), and socket inode. Correlating socket inodes to `/proc/<pid>/fd/` requires process permissions (accessible for user's own processes).

## 11. Filesystem & Persistence Readiness

### Current State
- `CanonicalEvent` supports an `action` and `summary` field, but LogIntel has no active file-system event collector or parser.
- Detection rule `proc_reconnaissance_tools` checks command strings; no rule checks file integrity.

### Telemetry Gap Analysis
- File integrity modification (`/etc/passwd`, `/etc/shadow`, `/etc/sudoers`) is unobservable in real time.
- Persistence mechanisms (cron drops in `/etc/cron.d/`, user crontabs in `/var/spool/cron/crontabs/`, SSH keys in `~/.ssh/authorized_keys`, and systemd service drops in `/etc/systemd/system/`) cannot be detected at modification time.

### Recommendation
- Do NOT implement an inotify/fanotify daemon across the entire filesystem (high CPU, buffer overflows).
- Implement bounded integrity monitoring over high-value persistence targets (`/etc/cron*`, `/etc/systemd/system/`, `~/.ssh/authorized_keys`) via periodic stat/hash checks or auditd path rules.

## 15. Collector Architecture

The current collector hierarchy in `apps/engine/src/logintel/collectors/`:
```text
Collector (base.py)
├── JournalCollector (journal.py: executes journalctl -o json)
└── FileTailer (file_tailer.py: stateful file tailing)
    ├── AuthLogCollector (auth.py)
    ├── SyslogCollector (syslog.py)
    └── KernLogCollector (kern.py)
```

### Architectural Evaluation
1. **Extensibility:** The `FileTailer` abstraction is robust. Adding `AuditLogCollector` for `/var/log/audit/audit.log` requires simply subclassing `Collector` and instantiating `FileTailer`.
2. **Offset Tracking:** `FileTailer` tracks both `byte_offset` and `current_inode`. If logrotate rotates a log, inode change or size truncation is detected, and offset resets safely to 0.
3. **Journal Cursor Tracking:** `JournalCollector` tracks `__CURSOR`. On restarts, it queries `journalctl` using `--after-cursor` rather than reloading history.

## 17. Event Loss & Reliability Model

When expanding into high-volume host telemetry (e.g. auditd or socket flows), event loss risks increase:

```text
Telemetry Source
       │ (1. Source loss: kernel audit queue overflow / ring buffer drop)
       ▼
Local Log / Socket
       │ (2. Rotation loss: logrotate deletes unread file)
       ▼
FileTailer / Collector
       │ (3. Backpressure loss: ingestion queue full)
       ▼
SQLite Database (4. Write loss: database locked / disk full)
```

### Forensic Distinction Invariant
The forensic engine must distinguish:
1. `NO EVENT OBSERVED`: Telemetry collector active; source operating; no activity occurred.
2. `TELEMETRY SOURCE UNAVAILABLE`: Source missing, permission denied, or daemon stopped.
3. `TELEMETRY SOURCE NOT CONFIGURED`: Collector disabled by configuration.
4. `TELEMETRY DROPPED`: Audit queue overflow indicated by audit kernel drop messages.

## 18. Temporal Model

Advanced telemetry requires multi-timestamp precision:
1. **Source Event Timestamp (`timestamp`):** When the operating system kernel recorded the event (e.g. audit epoch microseconds `msg=audit(1791255901.302:700)`).
2. **Ingestion Timestamp (`ingested_at`):** When LogIntel normalized and stored the event.
3. **Monotonic Sequence (`__SEQNUM` / `__MONOTONIC_TIMESTAMP`):** Preserves relative ordering across clock skews, NTP jumps, or daylight savings changes.

`CanonicalEvent` currently preserves `timestamp` and `ingested_at`. Monotonic attributes must be placed in `metadata_json` to prevent reordering artifacts during temporal reconstruction.

## 22. Forensic Preservation

For every advanced telemetry source, the following forensic invariants must be preserved:
1. **Raw Message Preservation:** The original auditd line, journal JSON, or procfs record must be stored verbatim in `raw_message`.
2. **Deterministic Fingerprint:** `event_fingerprint` computed as SHA-256 over `source:source_file:source_offset:raw_message`.
3. **Provenance Linking:** Every higher-level detection, alert, incident, finding, and hypothesis must link to `event_id` via `detection_evidence` and `case_evidence_references`.

Advanced telemetry will never bypass the canonical event ingestion path.

## 26. Security Model

### Threat Surface of Telemetry Collection
1. **Sensitive Data Exposure in Command Lines:** Passwords, API keys, and tokens passed as CLI flags (e.g. `curl -u user:pass ...`) appear in `/proc/<pid>/cmdline` and auditd `EXECVE` records.

3. **Privilege Boundaries:** Application runs under user permissions (`adm` group), preventing kernel compromise.

## 29. Failure & Recovery Model

| Failure Scenario | Collector Behavior | Recovery Strategy | Forensic Integrity Impact |
| :--- | :--- | :--- | :--- |

## 30. Test Strategy

Testing architecture for M6 implementation:

2. **Process Tree Reconstruction Tests:** Verify parent-child PID links across multi-generation process forks.
3. **PID Reuse Resilience Tests:** Synthetic replay of identical PIDs across distinct timestamps.
4. **Credential Masking Tests:** Ensure passwords in CLI flags are sanitized before DB insertion.
5. **High-Throughput Replay Tests:** Measure ingestion stability at 1,000 events/second using SQLite WAL mode.

## 33. Required Architectural Changes

1. **New Collector:** `AuditLogCollector` subclassing `Collector` and utilizing `FileTailer` targeting `/var/log/audit/audit.log`.
2. **New Parser:** `AuditParser` normalizing `type=EXECVE`, `type=PROCTITLE`, `type=SYSCALL`, and `type=USER_START` into `CanonicalEvent`.
3. **Credential Sanitizer Enhancement:** Add pattern-based masking in `sanitizer.py` for `-p <pass>`, `--password=<pass>`, `token=<tok>`, etc.
4. **Procfs Socket Reader:** Unprivileged reader module for `/proc/net/tcp` and `/proc/net/tcp6` to track active and listening sockets.
5. **Schema Migration Status:**
   - **Migration 6 for Telemetry Ingestion:** **NOT REQUIRED**.
   - **Migration 6 for Graph Entities & Relationships:** **DEFERRED to M6.8**.

## 35. Known Limitations

1. **Single-Host Workstation Scope:** Audit evaluates single-host Linux telemetry. Multi-host distributed collection is out of scope.
2. **Auditd Dependency:** Deep process execution collection relies on `auditd` being installed and active on the host.
3. **Docker Group Requirement:** Container socket access requires user membership in group `docker`.
4. **Historical Test Artifacts:** 6 pre-existing historical test failures in engine test census documented from M5 remain present and unchanged.
5. **eBPF Invasiveness:** In-kernel eBPF collection is deliberately excluded from early M6 to prevent kernel dependency breakage and root execution risks.
