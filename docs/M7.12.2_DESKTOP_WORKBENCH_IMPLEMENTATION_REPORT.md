## 4. Verified API Contracts Used

The frontend consumes exclusively verified endpoints established in M7.12.1:

| Method | Endpoint | Request Parameters / Body | Response Contract |
|---|---|---|---|
| `GET` | `/api/v1/cases/{case_id}/hosts` | Headers: `Authorization: Bearer <token>` | `CaseMultiHostDossier` JSON with `case_id`, `target_hosts`, `observed_hosts`, `hosts`, `visibility_gaps`, `discrepancies` |

No direct SQLite queries, undocumented routes, or unofficial schemas are used.

## 5. Behavioral Specifications

### A. Host Inventory
- Displays each associated host with its epistemic status:
  - `OBSERVED`: Host is actively generating telemetry within case timeframe.
  - `SCOPED BUT UNOBSERVED`: Host was explicitly targeted in case scope but has zero events in telemetry.
  - `UNSCOPED BUT OBSERVED`: Host appears in lateral traces or evidence but was omitted from target scope.
- Surfaces identity discrepancies (e.g., hostname mapped to multiple IPs or MACs).
- Evidence counts reflect only verifiable database rows; no fabricated metrics.

### B. Host Timeline
- Allows analyst to select any associated host and fetch its case-scoped events.
- Strict limit (default 50, max 200) and offset pagination with Next/Previous page controls.
- ISO timestamp range filtering (`time_start`, `time_end`).
- Preserves raw event attribution, source layer, and evidence provenance.

### C. Lateral Traces
- Visualizes reconstructed lateral movements between source and destination hosts.
- Displays hop sequences, technique names, and evidence IDs.
- Provides informative empty state when no lateral traces exist.
- Does not categorize traces as malicious without underlying threat evidence.

### D. Visibility Gaps
- Lists telemetry blind spots, catalog omissions, and unobserved hosts.
- Emphasizes epistemic boundary: absence of telemetry does NOT mean host was unaffected.

## 7. Authentication and Case Isolation Handling

1. **Token Propagation:** Every fetch attaches `Authorization: Bearer ${token}` retrieved from `getAuthToken()`.
2. **Error Trapping:**
   - `401 Unauthorized`: Displays authentication error prompt.
   - `403 Forbidden`: Displays permission denied state.
   - `404 Not Found`: Distinguishes case-not-found from host-not-associated.
3. **Race Condition Prevention:** In-flight request cancels and state clearing on `caseId` change prevent cross-case data leakage.
4. **Host Switching:** Selecting a new host resets offset and clears prior timeline data before fetching.
