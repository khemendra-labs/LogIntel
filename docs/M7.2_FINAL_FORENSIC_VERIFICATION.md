## 1. Executive Summary

Milestone M7.2 delivers the first new analyst-facing investigation capability of Program M7: **a deterministic, evidence-centric investigation timeline with interactive replay and synchronized graph/evidence navigation.**

The system enables security analysts to navigate an incident case chronologically while maintaining bi-directional synchronization between:
```text
Timeline  ↕  Graph  ↕  Evidence  ↕  Original Source
```

### Key Forensic Achievements:
1. **Deterministic Replay Engine:** Chronological replay with multi-speed controls (0.25x–4.0x), step-forward/backward, evidence-jumping, and random-access scrubbing. All replay sessions calculate deterministic Blake2b session fingerprints.
2. **Epistemic & Collection State Preservation:** Strict enforcement of `OBSERVED`, `INFERRED`, and `UNKNOWN` epistemic states, alongside M6 collection statuses (`SOURCE_AVAILABLE`, `RULE_NOT_CONFIGURED`, `NO_EVENT_OBSERVED`, `TELEMETRY_DROPPED`, `UNKNOWN`). Under no circumstances is `UNKNOWN` converted to `FALSE` or `INFERRED` promoted to `OBSERVED`.
3. **Strict Case Isolation:** All timeline projections, replay sessions, bookmarks, and exports strictly isolate cases. Cross-case data leakage is provably zero.
4. **Zero Forensic Mutation:** Replay is 100% read-only. Authoritative database integrity (`logintel.db` and `cases.db`) remains completely untouched with `integrity_check: ok` and zero foreign-key errors.
5. **No Schema Migration:** Migration 7 was explicitly evaluated and rejected. The existing schema and in-memory projection models satisfy all persistent and transient state requirements.

## 5. Unified Timeline

The unified timeline projects data from six operational evidence sources:
1. `events`: Canonical raw/host events (process executions, network sockets, auth).
2. `alerts`: Detection engine triggers.
3. `evidence`: Case-linked evidence references from `cases.db`.
4. `host_telemetry`: Linux host telemetry (auditd, PAM, sudo).
5. `incidents`: Incident life-cycle state changes.
6. `audit`: Governance audit trail records.

---

## 6. Timeline Data Semantics

### Deterministic Tie-Breaking Order:
When timestamps are equal, ordering is deterministic:
```text
Timestamp ASC → Source Layer Priority ASC → Source ID ASC → Timeline ID ASC
```
Never incidental SQLite order, never Python object hash order.

### Precision Preservation:
- `SECOND`: Timestamps with standard 1-second resolution.
- `MILLISECOND`: Sub-second precision preserved when forensically present.
- `UNKNOWN`: Unspecified precision flagged explicitly without fabricating fake fractional seconds.

---

## 7. Replay Architecture

- **State Model:** Replay position, play status, active frame, and playback speed are transient frontend React state. No unnecessary database writes occur during analyst scrubbing.
- **Controls:** Play, Pause, Step Forward/Back, Jump Start/End, Next/Prev Evidence, Speeds 0.25x, 0.5x, 1x, 2x, 4x.
- **Fingerprinting:** Each replay session computes a Blake2b session fingerprint covering all frames in order.

## 8. Graph Synchronization

When an analyst clicks or scrubs to an event in the timeline:
- The context inspector resolves all associated entities (`host`, `process`, `ip`, `user`).
- Entity tags in the inspector feature single-click pivots that activate the Attack Graph Visualizer (`onSelectEntityKey`).
- When selecting an entity in the graph, the timeline filters/highlights relevant chronological occurrences.

Clicking linked evidence directly opens the Canonical Event Forensics modal or Alert Inspection workbench.
