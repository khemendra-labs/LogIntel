## 1. Overview & Architectural Mission

In modern Linux host environments, systemd governs the entire process lifecycle, user sessions, service drops, and background daemons. Similarly, the Linux kernel surfaces low-level security events: out-of-tree and unsigned module loads, signature validation failures, and network promiscuous mode sniffing.

Prior to M6.6, systemd unit transitions fell back to generic syslog events (`SYSTEM_GENERIC`), and kernel module loading and promiscuous mode were unclassified.

**M6.6 delivers structured, deterministic, unprivileged telemetry for both systemd and kernel security layers:**

```text
SYSTEMD JOURNAL / SYSLOG / KERNEL RING BUFFER
                         ↓
SystemdParser / KernelParser (Extracts unit lifecycle, module loading, security anomalies)
                         ↓
CanonicalEvent Generation (SERVICE_STARTING, SERVICE_STARTED, SERVICE_FAILED, KERNEL_MODULE_LOAD, etc.)
                         ↓
SystemdUnitTracker (Inspects active unit states via systemctl)
                         ↓
Forensic Database (logintel.db events table, idempotent ingestion)
```

## 2. Systemd Service Lifecycle Telemetry

Implemented in `apps/engine/src/logintel/parsers/systemd.py`:
- **Unit Lifecycle State Detection:**
  - `Starting <unit>` $\rightarrow$ `SERVICE_STARTING`, `action = "UNIT_STARTING"`, `Severity.INFORMATIONAL`
  - `Started <unit>` $\rightarrow$ `SERVICE_STARTED`, `action = "UNIT_STARTED"`, `Severity.NOTICE`
  - `Stopping <unit>` $\rightarrow$ `SERVICE_STOPPING`, `action = "UNIT_STOPPING"`, `Severity.INFORMATIONAL`
  - `Stopped <unit>` $\rightarrow$ `SERVICE_STOPPED`, `action = "UNIT_STOPPED"`, `Severity.NOTICE`
  - `Failed to start <unit>` or `<unit> failed` $\rightarrow$ `SERVICE_FAILED`, `action = "UNIT_FAILED"`, `Severity.ALERT`
  - `Reloaded <unit>` $\rightarrow$ `SERVICE_RELOADED`, `action = "UNIT_RELOADED"`, `Severity.NOTICE`
- **Metadata Extraction:** Extracts `unit_name`, `unit_type` (service, socket, target, timer, mount), `description`, `main_pid`.
- **IOC Extraction:** Automatically extracts `unit_name` into the `iocs` list.
- **Journald Structured Attribute Support:** Seamlessly resolves `_SYSTEMD_UNIT` and `UNIT` attributes from native JSON journal streams.

## 3. Kernel Security & Module Telemetry

Enhanced in `apps/engine/src/logintel/parsers/kernel.py`:
- **Kernel Module Loading (`KERNEL_MODULE_LOAD`):**
  - Standard module load (`loading module <mod>`) $\rightarrow$ `Severity.NOTICE`
  - Out-of-tree / unsigned module load (`out-of-tree module taints kernel`) $\rightarrow$ `Severity.ALERT`
- **Kernel Module Unloading (`KERNEL_MODULE_UNLOAD`):**
  - Module unload (`unloading module <mod>`) $\rightarrow$ `Severity.NOTICE`
- **Kernel Security Anomalies (`KERNEL_SECURITY_ANOMALY`):**
  - Module signature verification failure (`module verification failed: signature and/or required key missing`) $\rightarrow$ `Severity.ALERT`, `Outcome.FAILURE`
  - Promiscuous mode device activation (`device <iface> entered promiscuous mode`) $\rightarrow$ `Severity.ALERT`
  - Promiscuous mode device deactivation (`device <iface> left promiscuous mode`) $\rightarrow$ `Severity.NOTICE`

## 4. Active Unit Tracking (`SystemdUnitTracker`)

Implemented in `apps/engine/src/logintel/systemd/tracker.py`:
- `list_units(unit_type)`: Discovers loaded and active units with status (`active`, `sub_state`, `description`).
- `get_unit_details(unit_name)`: Queries unit properties (`MainPID`, `ExecMainStatus`, `ActiveState`, `Description`, `User`).
- **Unprivileged Execution:** Runs without root permissions; handles unavailable or restricted environments gracefully.
- Distinguishes observed units from non-existent units (`load_state == "not-found"` returns 404).

## 5. REST API Endpoints

1. `GET /api/v1/investigations/systemd/units`:
   - Query active systemd units with optional `unit_type` and `state` filters.
2. `GET /api/v1/investigations/systemd/units/{unit_name}`:
   - Query detailed properties and process bindings for a specific unit.
